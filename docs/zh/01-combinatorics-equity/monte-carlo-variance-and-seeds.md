# 模拟误差从哪来：方差、标准误与固定种子

<!-- hands: 2 -->
<!-- terms: monte-carlo-simulation, variance, standard-error, sample-size, rng-seed, determinism, generated-artifact, equity, tie-chop, provenance, unverified-claim -->

## 本节目标 / Objectives

- 能解释标准误（stderr）与方差的差别，并写出它随样本量的变化规律。
- 能从目标精度反推需要多少次模拟。
- 会读引擎 `--json` 输出里的 `stderr`、`ci95`、`iterations`、`seed` 四个字段，并且在引用任何蒙特卡洛数字时把它们一起写出来。
- 能用实测数据说明：报告的标准误是**保守上界**，平分会把真实误差压下去。

## 前置知识 / Prerequisites

- `01-03` 精确穷举：本节所有"实测误差有多大"都要对一个已知的精确值来比。
- `00-03` 随机种子与确定性输出：知道 `--seed` 是干什么的。
- 期望与方差的定义：`Var(X) = E[X²] − (E[X])²`。

## 核心原理 / The principle

蒙特卡洛胜率不是一个数，是一个**随机变量**。它有自己的标准差，名字叫标准误：

```
stderr = sd(每次模拟的输赢量) / sqrt(样本量 n)
```

引擎把 `stderr` 作为一等字段写进结果（`pokergto.equity.EquityResult.stderr`），`--json` 会同时打印 `iterations`、`seed`、`stderr`、`ci95`。

**一个没有误差条的蒙特卡洛数字，就是一个戴着小数点面具的猜测。** `88.19%` 和 `88.19% ± 1.43pp`（`n = 2000`, `seed = 1`）说的是两件完全不同的事：前者假装自己知道得很多，后者告诉你它知道多少。

引擎报告的 `stderr` 取 `sqrt(p(1−p)/n)`，其中 `p` 是胜率——这是每次输赢量服从两点分布时的方差，因此它是真实方差的**上界**（下一节推导）。

## 推导 / Derivation

一次模拟给出一个输赢量 `X ∈ {1, 1/2, 0}`（赢、平分、输），概率 `w, t, l`，胜率 `p = w + t/2`。

```
E[X]   = w + t/2                = p
E[X²]  = w + t/4                = p − t/4
Var(X) = E[X²] − E[X]²          = p − t/4 − p²  =  p(1−p) − t/4
stderr = sqrt(Var(X)/n)         =  sqrt(p(1−p) − t/4) / sqrt(n)
```

三点结论：

1. **`t = 0` 时**，`Var(X) = p(1−p)`，引擎报的就是真实标准误。
2. **`t > 0` 时**，真实方差比报告的小 `t/4`。报告值因此**偏保守**——它不会让你低估风险。
3. **`1/sqrt(n)` 是唯一的收敛率。** 想把误差砍一半，样本量必须乘以 4；想砍到十分之一，乘以 100。没有第二条路。

**反推样本量。** 要求 95% 区间的半宽不超过 `e`：

```
n = z² · p(1−p) / e²        （z = 1.959964）
```

| 目标半宽 | `p = 88.19%`（AA 对 72o） | 最坏情形 `p = 50%` |
|---|---|---|
| ±0.50pp | 16,000 | 38,415 |
| ±0.25pp | 63,999 | 153,659 |
| ±0.10pp | 399,989 | 960,365 |

同一个精度在 `p = 0.5` 附近比在 `p = 0.88` 附近贵 2.4 倍，因为 `p(1−p)` 在 0.5 处最大：**硬币翻面比坚果牌更难测准。**

**95% 区间怎么读。** `ci95 = [p − 1.96·stderr, p + 1.96·stderr]`，`error_bar_95` 在两端把区间裁到 `[0, 1]`。它的含义是重复性陈述：同一条命令换 100 个种子，真值应该大约落在 95 个区间里——本节用实测的覆盖率检验了这句话。

## 直觉 / Intuition

把 2,000 次模拟想成"发 2,000 副牌"。你用这 2,000 副牌算出来的胜率，与用另外 2,000 副算出来的，**天生就差半个到一个百分点**；这不是失误，是抽样本身。种子决定你拿到哪 2,000 副。

所以：

- 换种子得到的差别，就是误差条应当报出的大小。本节实测：AA 对 72o，`n = 2000`，40 个种子的胜率区间 `[86.75%, 89.45%]`——**2.70 个百分点的跨度**，全部在"正常"范围内。
- 报告里出现第四个小数（`88.1937%`）时，先问它是精确穷举还是模拟。精确穷举的 `stderr` 是 0，`ci95` 退化成一个点，这两个字段本身就是"我付得起精确"的凭证。
- 引擎对同一 `seed` 输出逐字节相同，这是 `adr/0001` 的承诺；而"承诺"的内容是**同版本依赖下**可复现：`python tools/gen_all.py` 会把 Python 与 numpy 版本、以及它构建时所在的 commit 打到日志里，因为随机数流的稳定性是版本级的，不是宇宙级的。这些信息进日志而不进已提交的产物：一个要做字节比对的产物，只能取决于它的输入。

## 算例 / Worked examples

**例 1 — 真实散布：AA 对 72o，`n = 2000`，40 个种子。**
精确值 `88.1937%`（`01-03`）。40 次模拟（`seed = 1..40`）：均值 `88.1330%`，种子间标准差 `0.7101pp`，最小 `86.75%`、最大 `89.45%`。
把均值与精确值比：差 `0.0607pp`，除以标准误 `0.7101/sqrt(40) = 0.112pp`，得 **−0.54σ**——完全正常。**但单个种子的结果可以离真值 1 个百分点以上**，任何"我用 2000 次模拟算出 89.45%，所以 AA 有 89.45% 胜率"的说法都在欺骗听众。

**例 2 — `1/sqrt(n)` 定律实测（同一个对局，`seed` 各异）。**

| `n` | 报告的 stderr | 理论真实 stderr | 观察到的种子间 sd | 观察到的跨度 |
|---|---|---|---|---|
| 2,000 | 0.722pp | 0.718pp | 0.710pp（40 个种子） | 2.70pp |
| 20,000 | 0.228pp | 0.227pp | 0.225pp（8 个种子） | 0.73pp |
| 50,000 | 0.144pp | 0.144pp | 0.127pp（20 个种子） | — |
| 200,000 | 0.072pp | 0.072pp | 0.035pp（8 个种子） | 0.13pp |

理论列用 `sqrt(p − t/4 − p²)/sqrt(n)` 现算（AA 对 72o 的 `t = 0.3998%`，所以它与报告列几乎重合）。`n` 从 2,000 到 20,000 是 10 倍样本，误差变成 `0.722/0.228 ≈ 3.17` 倍——正是 `sqrt(10)`。最后一行的观察 sd（0.035pp）比理论值（0.072pp）小一半：**用 8 个种子估标准差，本身就有约 27% 的相对不确定度**（`1/sqrt(2(N−1))`），这一行是提醒你这个工具在样本少时也会说谎。

**例 3 — 覆盖率实测：真值落在区间里吗？** 对 AA 对 72o（真值 `88.1937%`）逐种子检查引擎给的 `ci95` 是否覆盖真值：

| `n` | 种子数 | 覆盖 |
|---|---|---|
| 2,000 | 20 | 20/20 |
| 20,000 | 20 | 18/20 |
| 50,000 | 20 | 19/20 |

期望是 95%，实测 100% / 90% / 95%。**20 个种子里"少覆盖 1 个"本来就完全正常**（不该因为一次 18/20 就怀疑引擎），这也是本节存在的理由：区间的含义是频率，不是保证。

**例 4 — 报告会保守：`AhKh` 对 `AsKs`。** 精确结果：胜率 `50.0000%`，赢 `7.1574%`，平分 `85.6853%`（`01-03` 的第一张表里的同类命令可复现）。
`t = 85.69%` 时真实方差 `= 0.25 − 0.2142 = 0.0358`，标准差 `0.1892`；报告用的上界是 `sqrt(0.25) = 0.5`。**比值 2.64。**
实测：`n = 2000`、20 个种子，种子间 sd `0.4253pp`（理论真实 `0.4237pp`，吻合），而报告 stderr `1.1180pp`。`n = 20000`：观察 `0.1109pp`、真实理论 `0.1338pp`、报告 `0.3536pp`。
**结论：平分局面的误差条被高估了近 3 倍。** 说"±1.1pp"其实是保守的，但如果你用它去判断两个对局的胜负率差别是否显著，你会误判"没有差别"。

**例 5 — 种子锁定。** 同一条命令（`AhAs 7d2s`，`n = 2000`，`seed = 7`）连续跑两次，输出逐字节相同（`equity = 0.88199`，`stderr = 0.00707888`）；把种子换成 8，胜率立刻变成 `88.875%`。**"可复现"从来不等于"不变"，它等于"别人能拿到你那个数"。**

## 实战牌局 / Live hands

**牌局 1（`hand.01-04-is-this-margin-real`）— 翻前，BTN 开池 2.5x，BB 3-bet 到 9x，Hero 拿 `AQo` 跟 6.5x。**

门槛是精确代数：`6.5/18.5 = 35.135%`。胜率只有模拟能给（`01-03` 牌局 2：翻前范围对范围要 8,800 万次评估）。测量：`equity "AQo" --range-villain "QQ+,AKs,A5s-A4s" --mode mc --iterations 20000 --seed 4 --json` → **37.075%，stderr 0.3415pp，95% 区间 [36.41%, 37.74%]**；把 `n` 提到 200,000（同种子）→ **36.473%，stderr 0.1076pp，区间 [36.26%, 36.68%]**。

- 判断"这个余量是不是真的"：门槛到点估计的距离是 `37.075 − 35.135 = 1.94pp`，等于 **5.7 个 stderr**。跟注的决定被数据支持。
- 但注意两次测量的点估计差了 `0.60pp`，比第二次测量的 2 个 stderr 还大——**这正是换种子会看到的事**。结论（跟注）没变，因为两次区间都在门槛之上；如果你只报点估计不报区间，别人就没有办法知道这一点。
- 反面：如果两次测量分别是 35.6% 和 34.9%（各自 ±0.3pp），那**不能**说"一次是跟一次是弃"，因为 35.135% 落在两个区间里。

**牌局 2（`hand.01-04-cheap-run-vs-exact`）— 单挑，翻牌 `Kh7h2d`，Hero 拿 `JhTh`，BTN 全下 100 进 100 底池。**

需要胜率 `33.33%`。这一手付得起精确：`01-03` 例 3 的 `39.4949%`。学员常做的却是随手跑一次默认模拟：`equity JhTh AcKc --board "Kh7h2d" --mode mc --iterations 2000 --seed 1` → **38.85% ±2.14pp**，95% 区间 `[36.70%, 41.00%]`。

- 精确值 `39.4949%` 落在这个区间里 ✓，而且决策（跟注）与精确一致 ✓。
- 但区间下界 `36.70%` 与门槛 `33.33%` 之间只剩 3.4 个百分点的余量：**一次 `n = 2000` 的模拟不足以回答"余量有多大"**，它只能回答"要不要跟"。翻牌圈一手牌对一手牌总共只有 990 个发展牌序，穷举它比模拟更快也更准——`01-03` 已经付过这笔钱了。**在付得起精确的地方用模拟，是把误差条免费送给对手。**

## 为何成立、何时失效 / Why it works, when it breaks

**成立的前提**：每次模拟独立同分布（同一联合分布里抽 (组合对, 牌序)），`n` 大到中心极限定理可用（扑克里几千次就够），`p` 不在 0 或 1 的极端附近。

**失效或要谨慎**：

1. **`p` 接近 0 或 1。** 正态近似在边界处失真；`error_bar_95` 把区间裁到 `[0,1]` 是止血，不是治疗。真要测 `2%` 级别的概率，`n` 得按 `p(1−p)` 重新算（例 1 的表格在最坏情形那一列给了量级）。
2. **报告值是上界。** `t > 0` 时被高估（例 4：2.64 倍）。做保守决策没问题，做显著性判断要换成 `sqrt(p − t/4 − p²)`。
3. **种子少的时候，"实测标准差"也是估计。** 8 个种子的 sd 有约 27% 的相对不确定度（例 2 最后一行）。用少量种子去"证明误差条写错了"是不合格的推理。
4. **跨版本的可复现性。** `numpy.random.default_rng(seed)` 的流由 numpy 保证同版本稳定；换 numpy 版本可能换流。已提交的生成物靠固定种子兜住这件事，而产出它们的 Python/numpy 版本由 `tools/gen_all.py` 打进日志，本节的所有数字都还需要你在本机复现一次。
5. **一次未被解释的实测偏差（诚实标注）。** 用 `01-03` 的防守图（884 组合）对互补的 442 组合，牌面 `Kh7h2d`，精确值是 `55.92%`。同一问题的模拟：`n = 20000, seed = 3` 给 `54.64% ±0.69pp`，`n = 200000, seed = 9` 给 `55.16% ±0.22pp`——两次都低于精确值，且第一次的偏差约是它自己报告 stderr 的 3.6 倍。本仓库**没有**解释这个现象；在解释之前，跨范围的胜率优先用付得起的精确模式，或把模拟结果当作带疑问的估计。复现命令见下面表格。

## 陷阱 / Common mistakes

1. **引用模拟数字不写 `n`、`seed`、误差条。**
   *代价*：读者无法判断这个数与门槛的距离是否显著，也无法复现。这是整本教材第 1 章就要禁掉的写法。引擎的 `--json` 已经把四个字段都打出来了，抄过去就行。
2. **以为样本量翻倍误差就减半。** 是 `1/sqrt(n)`：`n` 乘 4 才减半。
   *代价*：从 20,000 跑到 40,000 后看见数字没怎么动，就以为"收敛了"；把 ±0.3pp 的噪声当成策略差别，进而改掉一个本来正确的频率。
3. **拿两次不同种子的结果之差当作"真实变化"。** 例 1 里换种子能让 AA 对 72o 的胜率从 `86.75%` 走到 `89.45%`（`n = 2000`）。
   *代价*：在两个"看起来不同"的胜率之间做决策，实际只是抽样。先比区间，再比点估计。
4. **在付得起精确的地方模拟。** 翻牌圈一手对一手只有 990 个牌序（牌局 2）。
   *代价*：白白引入 1–2 个百分点的误差，还用"我的数字有十个小数位"来包装它。
5. **把保守上界读成真实误差。** 例 4 的 2.64 倍。
   *代价*：反过来的错——在平分局面上误判"差别不显著"，从而错过真实的结构性差异。

## 练习 / Drills

**先预测，后测量（本节的主练习）。**
用 `equity AhKh QdJs --mode mc --iterations 5000 --seed 1 --json`。
