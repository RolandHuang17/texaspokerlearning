# 从起手组合到手牌类别：每一类到底有几个组合

<!-- hands: 2 -->
<!-- terms: combos, hand-class, suited, offsuit, pocket-pair, hole-cards, range, grid-13x13, capacity, bluff-to-value-ratio, blocker -->

## 本节目标 / Objectives

- 能从四张花色这一条事实出发，独立推出 `6 / 4 / 12`，并验证 `13*6 + 78*4 + 78*12 == 1326`。
- 能把任意一个范围写法（`22+,ATs+`）换算成组合数，并说出它占 1326 的百分比。
- 能说清"按 169 类平均"和"按组合数加权"的差别有多大，以及在哪些算式里这个差别会决定结论的正负号。
- 会做后面每一章都要用的那道算术：我的诈唬范围有几个组合，价值范围有几个组合。

## 前置知识 / Prerequisites

- `00-01` 底牌、牌面与四条街：知道一手牌是两张底牌加五张公共牌。
- `00-02` 先推导再记忆：本节每一条数字都能用命令行重算，记住它没有意义。
- 组合数 `C(n,k)`：`C(4,2) = 6`，`C(13,2) = 78`，`C(52,2) = 1326`。

## 核心原理 / The principle

发牌空间的大小是 **1326**：`C(52,2) = 52*51/2 = 1326` 种具体的两张底牌。
分类空间的大小是 **169**：13 个对子 + 78 个同花类 + 78 个不同花类。
两者的比不是常数——**对子每类 6 个组合，同花每类 4 个，不同花每类 12 个**。

所以：任何"多少个范围"的问题（多大比例、几个组合、价值对诈唬几比几）都在 1326 上做；
任何"哪种牌"的问题（这手牌打不打）在 169 类上做。**把两类问题混在同一套权重里算，就是这套教材第 1 章要根治的病。**

## 推导 / Derivation

**每个对子 6 个组合。** `AA` 就是"从四张 A 里取两张"：`C(4,2) = 6`。同点的两张牌不可能同花，所以对子没有 `s/o` 之分。

**每个非对子同花类 4 个组合。** `AKs` 要求两张牌同花色，于是花色有 4 种选择（`AcKc`、`AdKd`、`AhKh`、`AsKs`），一旦花色定了，两张牌也就定了。`4`。

**每个非对子不同花类 12 个组合。** `AKo` 要求两张牌不同花色：先定 A 的花色（4 种），K 只能取其余 3 种花色，`4*3 = 12`。

**类的数量。** 对子 13 个（每个点数一个）；非对子的点数组合是 `C(13,2) = 78` 个，每个点数组合分裂成一个同花类和一个不同花类，所以同花 78、不同花 78。合计 `13 + 78 + 78 = 169`。

**合起来：**

```
13*6  +  78*4  +  78*12   =   78  +  312  +  936   =   1326
```

这条等式是引擎的断言之一（`pokergto.cards` 里 `ALL_COMBOS` 的长度必须是 1326，`HAND_CLASSES_169` 的长度必须是 169，否则模块直接抛 `InvariantError`）。跑一遍就能看到：

```bash
PYTHONPATH=src python -m pokergto range "22+" --json     # combos: 78.0, classes: 13
PYTHONPATH=src python -m pokergto range "22+,ATs+" --json # combos: 114.0, classes: 22, range_percentage: 8.5973
```

## 直觉 / Intuition

把 13×13 网格想成一张**格子大小不一样**的棋盘：对角线（对子）每格 6 个组合，右上三角（同花）每格 4 个，左下三角（不同花）每格 12 个。**一格不等于一个"手牌类"，一格等于 4、6 或 12 副具体的牌。**

于是有一句可以直接背下来的话：**同一个"看起来一样宽"的范围，写成同花还是写成不同花，组合数差三倍。**`AA,AKs` 是 10 个组合，`AA,AKo` 是 18 个组合——同样是两类牌，一个 0.75%、一个 1.36% 的起手空间。谁的防守范围里全是同花连接张，谁的实际组合数就比"类数"给出的印象小得多。

心智模型：类别是**目录**，组合是**库存**。下注尺度、频率、诈唬与价值的比例都在数库存；教练嘴里说的"这类牌打不打"才在数目录。

## 算例 / Worked examples

**例 1 — `22+,ATs+` 有几个组合。** 13 个对子 `13*6 = 78`；`ATs+` 按本仓库记法展开是 `ATs, A9s, ..., A2s` 共 9 个同花类（不含 `AKs/AQs/AJs`），`9*4 = 36`。合计 **114 组合**，占 `114/1326 = 8.597%`。
引擎同一命令给出的类数是 **22 类**，`22/169 = 13.018%`。**按类数估的范围比真值宽了 4.42 个百分点，是 1.51 倍**——这不是舍入误差，是把 4 组合的格子和 6 组合的格子当成等权造成的。

**例 2 — 一个纯同花范围。** `88+,A9s+,KTs+,QTs+,JTs,T8s+,96s+,85s+,75s,64s,54s`（典型的BTN跟3-bet范围骨架）：类数 53，`53/169 = 31.36%`；组合数 **226**，`226/1326 = 17.04%`。**差 1.84 倍。** 范围越偏同花，按类平均的错觉越严重；这也是为什么"我在 BTN 有 30% 的继续范围"这类话必须说明怎么数的。

**例 3 — `AKo` 还剩几个组合。** 牌面上已经有一张 A、对手亮了一张 K（`As` 与 `Kh` 都死了），`AKo` 从 12 掉到 **7**（引擎：`parse("AKo").with_removed(As, Kh)` → 7）。只看得见一张 `As` 时是 **9**；看见的是 `As` 和 `Ks` 时是 **6**——因为 `As` 杀掉 3 个组合、`Ks` 杀掉另外 3 个，而 `AsKs` 属于 `AKs`，两次删除不重叠。**同花的两张阻断牌比异花的两张删得更多。** 这是 `01-02` 的主题，这里先把"12 不是常数"这件事钉住。

**例 4 — 诈唬需要几个组合。** 半池下注的平衡比例是 **价值:诈唬 = 3:1**（见下一节的生成表，`s/(1+2s)` 那条闭式解）。如果这条行动线上我有 12 个价值组合，我必须配 **4 个诈唬组合**。4 个组合恰好是一个同花类（`55s` 这种没有，但 `A5s` 有 4 个），或者一个不同花类的三分之一（`12/3`）。
换句话说：范围写法里"用 `A5s` 诈唬"和"用 `KQo` 的三分之一诈唬"能给到同一个组合数，但它们在 13×13 图上占的格子数完全不同（1 格 vs 1 格但权重不同）。**比例是对组合说的，不是对格子说的。**

**例 5 — 底池比例换算。** 1326 这个数字要能随口换算：884 = `2/3`，442 = `1/3`，663 = 50%，114 ≈ 8.6%，22 ≈ 1.66%，6 = 0.45%，1 = 0.075%。后面所有"MDF 要我防守多少个组合"的算术都靠这几个锚点。

## 实战牌局 / Live hands

**牌局 1（`hand.01-01-river-bluff-blockers`）— 6 人桌现金，BTN 开池 2.5x，BB 跟注。牌面 `Ah 9d 6c 4s 2h`，底池 100，hero（BTN）考虑全下 60 诈唬。**

Hero 拿着 `Qc Jc`：没有对子，最大的牌只是一张 Q。对手"跟注"那一侧的每一个组合都比它大（顶对、set、两对），所以被跟注时这一手永远输——它是纯空气。诈唬能不能做，是组合数问题：

- 把对手"跟注的那部分范围"写成 `ATs-A2s, AJo, AQo, AKo, 99, 66`：扣掉牌面上那 5 张牌之后是 **57 个组合**（`AKo` 只剩 9 个，因为 `Ah` 死了；`99` 和 `66` 各剩 3 个，`A4s/A6s/A9s` 各剩 2 个）。
- 对手"弃牌的那部分范围"写成 `KQo, QJo, JTo, 88, 77, 55, 33`：扣掉牌面之后是 **60 个组合**。
- 加上 hero 手里的 `Qc Jc` 再做移除：跟注侧掉到 **53**，弃牌侧掉到 **48**。弃牌率 `48/(53+48) = 47.52%`。
- 门槛由 `02-03` 的代数给出：下 60 进 100 的底池，需要 `60/160 = 37.5%` 的弃牌率。47.52% > 37.5%，**诈唬成立**，每手的期望是 `0.4752*100 − 0.5248*60 = +16.04`。
- 关键处在这里：把 hero 换成 `Kc Jc`，弃牌侧只被删掉 9 个组合（不是 12 个），跟注侧同样剩 53，于是弃牌率变成 **49.04%**，期望 **+18.46**。两手牌都"什么都没中"，但**因为它们在对手范围里删掉的组合不同，每手相差 2.4 个筹码**。这个差别不数组合就永远发现不了。

这里的两个范围是本仓库为练习设定的示例范围（`reference`：任何一个都能逐项检查），组合计数与期望是 `derived`。复现（牌面移除走 `Range.with_removed`）：

```python
from pokergto.notation import parse
from pokergto.cards import Card
board = [Card.parse(c) for c in ("Ah", "9d", "6c", "4s", "2h")]
hero  = [Card.parse("Qc"), Card.parse("Jc")]
parse("ATs-A2s,AJo,AQo,AKo,99,66").with_removed(*board).total_combos()   # 57.0
parse("KQo,QJo,JTo,88,77,55,33").with_removed(*board).total_combos()     # 60.0
parse("ATs-A2s,AJo,AQo,AKo,99,66").with_removed(*board, *hero).total_combos()  # 53.0
parse("KQo,QJo,JTo,88,77,55,33").with_removed(*board, *hero).total_combos()    # 48.0
```

翻前这两段写法的组合数分别是 84 和 60，所以牌面那五张牌只从跟注侧删掉了 27 个组合——**这正是必须做减法、不能只看类数的原因**（`ATs-A2s,AJo,AQo,AKo,99,66` 一共才 14 个类，类数上看不出任何变化）。

**牌局 2（`hand.01-01-three-bet-call-count`）— BTN 开池 2.5x，BB 3-bet 到 9x，其余弃牌，底池 12x，hero（BTN）拿着 `AQo` 要跟 6.5x。**

- 跟注需要的胜率：`6.5/(12+6.5) = 6.5/18.5 = 35.14%`。这是纯代数，与对手是谁无关。
- 如果 BB 的 3-bet 范围只有价值 `QQ+,AKs`：**22 个组合**（`18` 个对子 + `4` 个 `AKs`）。`AQo` 对它的胜率是 **23.88% ±0.59pp**（蒙特卡洛，`n = 20000`，`seed = 4`；把 `n` 提到 200000 得到 23.79% ±0.19pp）——翻前跨范围的精确穷举要 88,364,640 次评估（`2,598,960 × (12 + 22)`），引擎会拒绝并告诉你为什么，见 `01-03`。23.88% < 35.14%，**弃牌**。
- 如果 BB 的范围里加了 `A5s-A4s` 这 **8 个**诈唬组合（合计 30 个）：同样的 `AQo` 胜率变成 **37.08% ±0.67pp**（`n = 20000`, `seed = 4`；`n = 200000` 时 36.47% ±0.22pp）——**过线，跟注**。
- 结论完全由组合数驱动：多出的那 8 个组合把价值:诈唬从"没有诈唬"变成 `22:8 = 2.75:1`，也把 hero 的决定从弃牌翻成跟注。**这就是为什么要数库存，不要数目录。**

```bash
PYTHONPATH=src python -m pokergto equity "AQo" --range-villain "QQ+,AKs" \
    --mode mc --iterations 20000 --seed 4 --json
PYTHONPATH=src python -m pokergto equity "AQo" --range-villain "QQ+,AKs,A5s-A4s" \
    --mode mc --iterations 20000 --seed 4 --json
```

## 范围图 / Range chart

上面这张图是 `02-03` 的**半池 MDF 底线**：它必须覆盖 `2/3` 的起手空间，也就是 **884 个组合**（`1326*2/3`）。artifact 里写的 `total_combos = 883.999996`，不是笔误：那一格里 `84o` 的频率被固定成六位小数 `0.333333`，而 `12*0.333333 = 3.999996`。这是 ADR-0001"固定小数格式"的代价，也是为什么组合数要当成**带来源的数**而不是整数来读。

读法有三层：

1. 图上有 **114 个非空格子**（113 个填满 + `84o` 只填三分之一）。按格子数是 `114/169 = 67.46%`，按组合是 `884/1326 = 66.67%`。**这张图恰好是两者几乎相符的少数情形**——因为它是"按牌力从高到低填格子"的产物，填进去的格子在对子/同花/不同花之间接近混合均匀。换一个"全同花"的范围去做同样的比较，差距会拉到例 2 那种 1.84 倍。
2. `84o` 那一格是**混合频率**：`0.333333 * 12 = 4` 个组合。以后遇到 solver 输出里的 `0.5` 一类频率，先乘 `4/6/12` 再谈比例。
3. 图本身不含移除效应。牌面上如果有一张 `Ah`，这张防守图会少 **43 个组合**（`884 → 841`，占 1326 的 `63.42%`）；如果死的是 `2h`——那一格根本不在范围内，**一个组合都不少**。这就是 `01-02` 的入口。

## 为何成立、何时失效 / Why it works, when it breaks

**为什么成立**：`6/4/12` 只用到"每种花色各一张、共四种花色"这一条事实，不依赖任何牌力、任何玩家、任何尺度。它是发牌机的性质，不是策略的性质。

**什么时候不能直接用**：

1. **有牌可见时（移除效应）。** `12` 不再是 `12`：牌面、你自己的底牌都会删组合（例 3）。本节给的是"没有任何信息时"的上界，`01-02` 专门处理减法。
2. **频率不是整格时。** 混合策略下每格的组合数可以是小数（`84o` 那一格的 4 个组合来自 `0.333333*12`）。比例仍然成立，但"半个组合"没有物理对应物，它表示同一手牌在不同街用不同频率打。
3. **记法表达不了物理子集。** `pokergto.notation` 只能写到"类"这一层，写不出"只要 `AsKs` 这一张"。当你真的需要挑某一张花色时，`to_spec()` 会把范围标记为 `lossy`——这不是小瑕疵，它意味着图上的一个格子并不总是同一个物理集合。
4. **多人底池。** 组合数还是那些组合数，但"比例"的目标会变：`07-01` 里三人、四人底池的价值:诈唬结构不是本节这张表。
5. **锦标赛。** 组合数仍然正确，但 `02-04` 那张表的前提是筹码线性；ICM 下 `3:1` 会变形（第 12 章）。

## 陷阱 / Common mistakes

1. **用 169 类平均来报范围宽度。** 例 1 里 `22+,ATs+` 按类是 13.02%，按组合是 8.60%。
   *代价*：你会以为自己的防守范围比实际宽 1.5 倍，于是把真正只有 8.6% 库存的范围当成 13% 的配额去承担 MDF——按 `02-03` 的话说，这是让对手用任意两张牌诈唬就能赚钱。用 `python -m pokergto range "<spec>" --json` 看 `combos` 与 `range_percentage` 两个字段，一分钟就能纠正。
2. **把 `6/4/12` 当成永远成立。** 例 3：`AKo` 在两张可见牌之后只剩 7 或 6 个组合，`99` 在牌面有一张 9 之后只剩 3 个。
   *代价*：你以为对手"最多有 12 个 `AKo` 价值组合"，于是算出他的诈唬占比过高，结果用一个根本不够量的抓诈唬范围去跟注。真实数字用 `parse(spec).with_removed(*cards)`。
3. **拿"类"去配价值:诈唬比例。** `3:1` 是组合的比例。用"3 个价值格子配 1 个诈唬格子"去执行，实际配出来的可能是 `3*12 : 1*4 = 9:1`（价值全是不同花、诈唬是同花）或者 `3*4 : 1*12 = 1:1`。
   *代价*：牌局 1 里 `48` 个弃牌组合与 `53` 个跟注组合之间的边际本来只有 10 个百分点的弃牌率余量，比例配错一档就变成负期望。数组合，不要数格子。
