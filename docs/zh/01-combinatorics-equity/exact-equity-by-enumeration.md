# 穷举胜率：把补牌数换成每一街的精确概率

<!-- hands: 2 -->
<!-- terms: equity, win-probability, outs, rule-of-two-and-four, tie-chop, showdown, flop, turn, river, runout, board, monte-carlo-simulation, combos -->

## 本节目标 / Objectives

- 能从一个已知牌的数量出发，算出任意街还剩多少个发展牌序，并说清 `1176 / 1081 / 990` 各自的适用条件。
- 能用闭式组合数推导听牌概率（不靠模拟），并给二四法则的误差定出正负号。
- 能说清精确胜率与"赢的概率"差在哪里（平分记半份）。
- 知道穷举的代价怎么估，以及引擎在什么规模上会直接拒绝。

## 前置知识 / Prerequisites

- `01-01` 组合数与 `1326`：精确枚举的权重单位仍然是组合。
- `01-02` 移除效应：已知牌越少，剩下的牌池越大。
- `00-02` 先推导再记忆：本节的每个数字后面都跟着一条可执行命令。

## 核心原理 / The principle

**精确胜率 = 把所有可能的发展牌序穷举一遍，用同一个七张牌评估器打分，赢记 1、平分记 1/2、输记 0，再按组合权重求平均。**

```
equity = (wins + ties/2) / (wins + ties + losses)
```

代价是一条乘法：

```
成本 ≈ 发展牌序数 × (hero 组合数 + villain 组合数)
```

牌序数只由"已经知道几张牌"决定：牌堆剩 `52 − 已知`，还要发 `5 − 牌面张数` 张，于是

```
牌序数 = C(52 − 已知, 5 − 牌面)
```

`pokergto.equity.EquityResult` 里 `equity == wins + ties/2` 是**断言**而不是约定：不满足就抛 `AssertionError`。这条断言就是"胜率不等于赢率"的机械表达。

## 推导 / Derivation

**牌序数（下表每一行都用 `runout_boards` 实测过，不是查表）。**

| 已知什么 | 已知牌数 | 还要发 | 牌序数 | 实测 |
|---|---|---|---|---|
| 只有翻牌圈牌面 | 3 | 2 | `C(49,2)` | 1176 |
| 翻牌圈 + 自己的底牌 | 5 | 2 | `C(47,2)` | 1081 |
| 翻牌圈 + 两家底牌 | 7 | 2 | `C(45,2)` | 990 |
| 转牌圈 + 两家底牌 | 8 | 1 | `C(44,1)` | 44 |
| 翻前，什么都不知 | 0 | 5 | `C(52,5)` | 2,598,960 |
| 翻前，两家底牌已知 | 4 | 5 | `C(48,5)` | 1,712,304 |

**三档"翻牌圈"必须分清。** `1081` 是**你知道牌面和自己底牌**时的未来空间——补牌概率那条 `9/47` 就活在这一档（`47 = 52 − 3 − 2`）。`990` 是**两家的牌都摊开**时的空间，一手牌对一手牌的精确胜率就在这一档上枚举。`1176` 是**只有牌面**的空间：范围对范围时引擎不知道你会拿哪两张，只能先把 49 张里取 2 全跑一遍，再在每个牌序上把"用掉了牌面牌的组合"屏蔽掉。把这三档混用，一节讲听牌的课就会算错分母。

**听牌概率的闭式。** 未见的牌 `u` 张，其中 `o` 张让你成牌：

- 下一张成牌：`o/u`。9 张补牌、`u = 47` → `9/47 = 19.1489%`。
- 两张（转牌+河牌）成牌：`1 − C(u−o, 2)/C(u, 2)`。`1 − C(38,2)/C(47,2) = 1 − 703/1081 = 34.9676%`。

**二四法则从哪来。** 把 `o/u` 的分母近似成 50，就得到 `2o%`——所以它永远**低估**（真实分母是 47）。两张牌时把两次 `2o%` 直接相加，得 `4o%`，它把"两次都成"的那部分重复计了一次，于是补牌多的时候**高估**；补牌少到一定程度，近似里省下的项反而占上风，它就变成**低估**。生成表里 6 outs 那一行就是证据：精确 24.14%、法则 24%，法则**低**了 0.15 个百分点；7 outs 起法则开始高估。

## 直觉 / Intuition

穷举不是"暴力"，是**把未来摊在桌上数**。990 个河牌局面一只手一只手比完，向量化评估器的实测吞吐是 313,984 手/秒，也就是每手约 3.2 微秒——真正的问题只在范围：把 990 换成 1176，把 2 只手换成 1326 个组合，成本立刻是百万级。

三个可以随身带的锚点。时间是在作者的本机（py3.12、Windows、2026-10-07）用 `pokergto.evaluator` 里的向量化评估器实测的；这条吞吐一旦退化，`tools/cost_probe.py` 就会让构建失败。

- 翻牌圈一手牌对一手牌：**990**，毫秒级，永远该用精确。
- 翻前一手的对一手：**1,712,304**，实测 17.3 秒，值得为"教科书数字"跑一次（本节的 88.19% 就是这么来的）。
- 翻前范围对范围：**上千万到上亿次评估**，引擎会拒绝；这正是 `01-04` 存在的理由。把评估器向量化之后，同样的枚举快了 4.8 到 20.4 倍，但**这一档一个字没变**：完整的精确 169×169 类别矩阵是 `2,598,960 × 225,780 = 5.87e11` 次评估，按实测吞吐约 740 小时——这就是 `adr/0006` 撤回"翻前可以精确枚举"那句承诺的原因。

## 算例 / Worked examples

**例 1 — 翻前精确：`AhAs` 对 `7d2s`。** 1,712,304 个牌序，全枚举得

```
equity 88.1937%   wins 87.9938%   ties 0.3998%   losses 11.6064%
```

```bash
PYTHONPATH=src python -m pokergto equity AhAs 7d2s --mode exact --json
```

注意 `ties` 那 0.4%：AA 对 72 offsuit 也会平分（牌面自己成顺、成同花、成葫芦）。**"AA 有 88% 胜率"这句话里的 88% 是含平分的份额，不是"赢的概率"（87.99%）**。差 0.2 个百分点，但在算全下期望值时它就是你该拿的那一半底池。

**例 2 — 三个被反复引用的翻前数字，全部当场重算。**

| 对局 | 精确胜率 | 赢 | 平分 |
|---|---|---|---|
| `KsQh` 对 `AcAd` | 13.6519% | 13.4882% | 0.3273% |
| `AhKh` 对 `QdJs` | 66.6408% | 66.4187% | 0.4441% |
| `Td9d` 对 `AcKc` | 38.7187% | 38.4852% | 0.4670% |

三条命令分别是 `equity KsQh AcAd --mode exact`、`equity AhKh QdJs --mode exact`、`equity Td9d AcKc --mode exact`。**注意 `Td9d` 对 `AcKc` 是 38.72%，而它常被写成"约 40%"**：那 1.3 个百分点在"要不要跟全下"的边界上足够决定正负号。
同一个对局改成模拟：`equity KsQh AcAd --mode mc --iterations 20000 --seed 7` 给出 13.69% ±0.48pp，落在精确值 13.6519% 的误差条内——这是你对任何一次模拟最低限度的要求。

**例 3 — 翻牌圈精确，990 个牌序。** `JhTh` 对 `AcKc`，牌面 `Kh7h2d`：

```
equity 39.4949%   wins 39.4949%   ties 0.0%
```

```bash
PYTHONPATH=src python -m pokergto equity JhTh AcKc --board "Kh7h2d" --mode exact
```

Hero 有 9 张红心补牌 + 一张 Q 的卡卡顺，其中 `Qh` 两个集合重叠；`ties` 为 0 是因为这个牌面结构下两人不会做出同一手牌。

**例 4 — 补牌数不该相加。** 牌面 `9h8h2s`，hero `JhTh`：

```python
from pokergto.equity import outs_from_enumeration
outs_from_enumeration(hero, board, improve_to="FLUSH")     # 9 张
outs_from_enumeration(hero, board, improve_to="STRAIGHT")  # 15 张（同花也算"至少顺子"）
```

两个集合的并不仍是 **15**：真正的顺子牌只有 `7c 7d 7s Qc Qd Qs` 六张，另外九张是红心（`7h` 同时属于两侧）。口头上的"同花 9 + 顺子 8 = 17 张补牌"错了两处：**`Th` 在你手里，不是 4 张 T**；`7h` 被数了两遍。
用错的分母往下算：`17` 张补牌到河牌是 `1 − C(30,2)/C(47,2) = 59.76%`，而真实的 15 张是 `54.12%`——**5.6 个百分点的虚高**，足够把一个跟注变成送钱。

## 实战牌局 / Live hands

**牌局 1（`hand.01-03-flop-allin-exact`）— 单挑，翻牌 `Kh7h2d`，底池 100。Hero 拿着 `JhTh` 面对 BTN 的全下 100。**

- 需要胜率：跟 100 进 300 → `100/(100+200) = 33.33%`（`02-02` 的 `B/(P+2B)`）。
- 拥有胜率：**39.4949%**，`mode=exact` 枚举 990 个发展牌序，无误差条。
- 边际 +6.2 个百分点 → **跟注**。这里没有近似、没有"约等于四成"：一手牌对一手牌在翻牌圈永远付得起精确。
- 检查一遍成本公式：`990 × (1 + 1) = 1,980` 次评估——比 `mode="auto"` 的默认阈值 `AUTO_EXACT_BUDGET = 250,000` 低两个数量级，所以自动模式也会选精确。

**牌局 2（`hand.01-03-range-too-wide-for-exact`）— 翻前，BTN 开池 2.5x，BB 3-bet 到 9x，Hero（BTN）拿着 `AQo` 要跟 6.5x。**

- 门槛 `6.5/18.5 = 35.14%`，与 `01-01` 牌局 2 相同。
- 想精确算 `AQo`（12 个组合）对 `QQ+,AKs`（22 个组合）：牌序是 `C(52,5) = 2,598,960`，成本 `2,598,960 × (12 + 22) = 88,364,640` 次评估，超过引擎硬阈值 `EXACT_EVAL_BUDGET = 4,000,000`，于是 `mode="exact"` 抛 `BudgetExceeded`，并把牌序数、组合数与替代方案一起写在消息里。
- 出路只有两条：把问题缩到付得起精确的规模（翻牌圈、一手对一手），或者用蒙特卡洛并接受误差条（`01-04`）。本节选后者示范：`equity "AQo" --range-villain "QQ+,AKs" --mode mc --iterations 20000 --seed 4 --json` → **23.88% ±0.59pp**（95% 区间），低于 35.14%，弃牌。
- 诚实标注：这条 MC 结论的可信度取决于误差条与种子，见 `01-04`；把它当成"精确答案"就是本节要防的错。

## 为何成立、何时失效 / Why it works, when it breaks

**成立的前提**：评估器正确（`table.01-05.hand-class-counts` 的九数之和就是对它最强的自检），发牌分布正确（每个牌序等权、组合权重来自 `01-01`），平分记半份。三条都在代码里，不在口头约定里。

**什么时候不该用精确：**

1. **成本。** `发展牌序 × 组合数` 一旦上到千万级，引擎直接拒绝（牌局 2）。别去绕过硬阈值，那是设计出来的护栏（`adr/0001`）。
2. **分母选错。** 用 `1081` 去解释一手牌对一手牌的枚举（真实 990），或者用 `990` 去解释"我只知道牌面"的空间（真实 1176），得到的胜率会与任何可复现的计算不符。
3. **胜率不是钱。** 精确胜率告诉你份额，不告诉你实现率。被支配的牌（`KsQh` 对 `AcAd` 的 13.65%）之所以难打，是因为它赢的时候多半只赢底池、输的时候输一整个范围（`01-06`）。
4. **文档与代码的措辞不一致。** `src/pokergto/equity.py` 的模块注释把 `C(47,2) = 1081` 称作"只知道牌面时"的空间，而 `runout_boards(board)` 实测给的是 `C(49,2) = 1176`；`1081` 对应的其实是"牌面 + 自己底牌"这一档。本节按实测的三档写，并把这条措辞差异记在下面那张表里（**UNVERIFIED**：需要一次代码注释修订或一条测试来关闭）。

## 陷阱 / Common mistakes

1. **把 `1081 / 990 / 1176` 当同一个数。**
   *代价*：所有"翻牌圈还剩几种可能"的换算错 9%–19%，而听牌概率正好建立在这个分母上。用 `runout_boards` 打印一次长度，比背三个数可靠。
2. **把胜率念成赢率。** AA 对 72o 的 88.19% 里含着 0.40% 的平分；`KsQh` 对 `AcAd` 的 13.65% 里含着 0.33%。
   *代价*：在算全下 EV 时把一半底池记成零，`equity != wins`，边界处正负号会翻。引擎的 `EquityResult` 用断言防住了自己，你的口算没有。
3. **听牌补牌直接相加。** 例 4：真实 15 张被念成 17 张。
   *代价*：到河牌的胜率虚高 5.6 个百分点，跟注变送钱。用 `outs_from_enumeration` 让引擎给集合，自己做并集。
4. **以为"四法则一定高估"。** 6 outs 及以下它是**低估**（24% vs 精确 24.14%）。
   *代价*：把"法则会替我留余量"当成安全垫，在小补牌数的听牌上跟了本不该跟注的注。生成表的误差列就是为了让这一档看得见。

## 练习 / Drills

- 不查表推出：转牌圈已知两家底牌时的牌序数、河牌圈的牌序数、翻牌圈只知牌面的牌序数。然后用 `runout_boards` 打印长度核对（44 / 1 / 1176）。
