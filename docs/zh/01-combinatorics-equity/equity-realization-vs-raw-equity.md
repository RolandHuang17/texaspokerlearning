# 胜率不等于拿到手的钱：胜率实现为何低于名义胜率

## 本节目标 / Objectives

- 能分清两个量：引擎算出的**名义胜率**（摊牌份额）与你在一张牌桌上真正拿到的**实现胜率**，并说出前者回答的是什么问题、后者为什么不在它的范围内。
- 能列出至少四条压低实现胜率的结构性原因，并说出其中哪几条在这套代码里可算、哪几条只是建模假设。
- 能指出最容易把名义胜率当成钱的那一类手牌，并给出它在引擎里的三个计算证据。
- 能在别人说出"顶对打八折"这类数字时，准确说出它属于哪一类来源，以及要把它变成 `derived` 需要什么。

## 前置知识 / Prerequisites

- `01-03` 精确枚举胜率：`equity = wins + ties/2`，以及它是在发展牌序上平均出来的份额。
- `01-05` 七张牌评估器：为什么平局会占掉 97.09% 这样一个夸张的比例。
- `02-02` 跟注所需胜率：`B/(P+2B)` 这个门槛。

## 核心原理 / The principle

引擎给出的只有一个东西：如果钱在摊牌时关上，你在这个底池里的**份额**。

```
raw equity = (赢的加权分支数 + 平分/2) / 全部加权分支数
```

它在数学上是一个上限之外的别的东西：它既不是"你会赢的频率"，也不是"你会拿走的钱"。实现胜率想说的是后者：

```
realized equity = raw equity × r,   r ∈ [0, 1]
```

`r` 由位置、谁最后行动、你能不能便宜地看到摊牌、以及 SPR 决定的"钱能在什么价位关上"共同给出。**本仓库没有任何函数返回 `r`。**这不是遗漏，是当前的边界：`ROADMAP.md` 把"Equity realization vs SPR as a computed quantity rather than a rule of thumb"（胜率实现作为计算量，而不是经验法则）写在 M8，也就是 1.0 之后的条目里。所以本节所有关于 `r` 的陈述都带 **UNVERIFIED / 未核验**，并且说明它会怎么被核验；所有关于 `raw equity` 与阈值的数字都是引擎现算的。

> !!! note "来源 / Provenance"
>     可计算部分：`src/pokergto/equity.py`（份额）、`src/pokergto/odds.py` 与 `src/pokergto/spr.py`（阈值、SPR、隐含赔率代数）。实现率本身：无函数、无生成物，属建模假设，见 `ROADMAP.md` 的 M8。

## 推导 / Derivation

**第一步：把引擎算的那个量写清楚。** `range_equity` 在每一个合法的发展牌序上评估两手牌，按组合数加权，返回三个频率与它们的合成：

```
equity = wins + ties/2          （构造时断言，不满足就抛异常）
```

`python -m pokergto equity "AhJh" "KdKc" --board "Qh9h2s"` → 990 个牌面，精确：equity **46.5657%**，wins 46.5657%，ties **0.00%**，losses 53.4343%。注意 ties = 0：这一对牌在任何发展牌序上都不会打平。

**第二步：阈值侧也是引擎的。** 同一个手数要过两道不同的门：

```
跟一条下注：      e ≥ B/(P + 2B)            # P=6, B=3 → 25.00%
把整个筹码关上：  e ≥ SPR/(1 + 2·SPR)       # 由 spr() 与 all_in_equity_needed_from_spr()
```

`python -m pokergto spr --stack 97.5 --pot 5` → SPR 19.500 → 需要 **48.75%**；`--stack 92 --pot 16` → SPR 5.750 → **46.00%**；`--stack 3.25 --pot 6.5` → SPR 0.500 → **25.00%**。这三个数是本节唯一和"实现"沾边、却能被算出来的东西：**名义胜率没变，够钱的门槛随筹码结构移动**。

**第三步：仓库里唯一两处把未来的钱写进公式的地方。** `pokergto.spr` 提供：

```
隐含赔率：   e ≥ B / (P + 2B + future_winnings)
反向隐含：   e ≥ (B + future_losses) / (P + 2B)
```

在 `P = 6, B = 3`（半池）上代入：

| 假设 | 需要的胜率 |
|---|---|
| 无未来钱（只有当前这一注） | 25.00% |
| 未来能再赢 5 | 13.70% |
| 未来能再赢 20 | 7.04% |
| 未来损失 3 | 50.00% |

关键在"代入"这两个字：`future_winnings` 与 `future_losses` **不是算出来的**，是你填进去的。引擎能保证的只是代数对：给定你假设能在击中后多拿 5 个筹码，需要胜率就是 13.70%。它不能告诉你那 5 个筹码会不会真来。

**第四步：未来的钱有上界，这个上界是可算的。** 后续街最多能再搬动的钱，受限于有效筹码。`P = 6, B = 3`、9 张补牌、只看下一张牌时（`draw_probability(9, 47, 1)` = **19.1489%**），要让跟注在期望上打平，需要的未来钱是

```
3 / 0.191489 − (6 + 6) = 3.67 个筹码
```

把 `implied_odds_break_even_equity(6, 3, 3.6667)` 代回去正好得到 19.1489%，这是自洽校验。可如果两家身后只剩 3.25，最好的情况也只是 `3/(6+6+3.25)` = **19.67%** 需要量，仍然高于 19.15%：**浅筹码把隐含赔率压回了它自己的天花板**，于是这一张牌不能跟；要看两张牌（`draw_probability(9, 47, 2)` = **34.9676%**）才过关。这一条完全是算出来的，也是"实现率不完全靠感觉"的那部分证据。

**第五步：最硬的计算证据——份额可以几乎全来自平分。** `AcKd` 对 `AdKh`（同一个 AKo 类别，只是花色错位）翻前精确枚举 1,712,304 个牌面：**equity 49.6327%，其中 wins 只有 1.09%、ties 高达 97.0872%**。这手牌的名义胜率接近一半，但它"全拿"的分支只有 1.09%。任何把 49.63% 直接乘以底池去定价的做法，都在假设一堆几乎不存在的胜利。

## 直觉 / Intuition

三个问题分开问，别用同一个数字回答三遍：

1. 钱关上时我占多少份额？——这是名义胜率，引擎能给。
2. 我能不能便宜地走到摊牌？——这是位置与对手行动线的问题，引擎给不了。
3. 钱会在什么价位关上？——这是 SPR，引擎能给门槛。

名义胜率只回答第 1 问。实现率之所以低，最常见的原因不是"你打得怂"，而是：**你的份额集中在那些你必须再掏钱才能兑现的分支上**。同一手 46% 的牌，在"我最后行动、可以不花钱看河牌"和"我每街都得先表态"之间，拿到的钱不是一个数。

最容易记的一句话：平分不是赢，弃牌不是零，名义胜率不是应收款。

## 算例 / Worked examples

**例 1 — 同花听牌加两张高牌。** `AhJh` 在 `Qh9h2s`，对手范围 `KdKc`。名义胜率 46.5657%（精确），ties 0.00%。面对半池（`P = 6, B = 3`）需要 25.00%：门槛过得去，余量 21.57 个百分点。但 46.5657% 是"如果钱关上"的份额——要在翻牌圈就把它收进来，前提是剩下的 53.4343% 分支里你能廉价脱身。后半句是实现率问题，本节不给百分数。

**例 2 — 同一手牌，三个筹码结构。** `Td9d` 对 `AcKc` 翻前精确枚举：**38.7187%**（wins 38.4852%，ties 0.4670%）。这个数不随筹码变化，能随筹码变化的是门槛：

| 场景（有效筹码 / 底池） | SPR | 全下需要 | 38.72% 够吗 |
|---|---|---|---|
| 97.5 / 5（100 深度单加注入池） | 19.500 | 48.75% | 差 10.03 个百分点 |
| 92 / 16（3-bet 池） | 5.750 | 46.00% | 差 7.28 个百分点 |
| 3.25 / 6.5（已经很浅） | 0.500 | 25.00% | 超 13.72 个百分点 |

结论只到"钱关上的价位"为止：**同一手名义胜率，在浅筹码里够全下，在深筹码里连 3-bet 池的都关不上**。至于这手牌在深筹码里到底能实现多少，本节不填数——那是 M8 的活。

**例 3 — 被压制的顶对。** `K9s` 对 `KQo,KQs`，牌面 `Kh8c3d`，精确枚举 1,176 个发展牌序：**equity 16.6246%，wins 14.8485%，ties 3.5522%**。面对 1/3 池（`P = 6, B = 2`）需要 20.00%：**名义胜率本身就不过关**，差 3.38 个百分点。这一手的坏消息有两层：一层是可算的（份额低于门槛），另一层是结构性的（它过关的方式几乎只有"击中两对或三条"，而那需要再掏钱）——第二层是实现率的语言，不写成数字。

**例 4 — 反向隐含赔率的算术。** 承上，`P = 6, B = 3`（半池）时若你预计"每次击中还要再付 3"，`reverse_implied_odds_penalty(6, 3, 3)` 给出需要胜率 **50.00%**，是原始 25.00% 的两倍。同一手牌，一个假设从"不付钱"改成"付 3 个筹码"，门槛直接翻倍。这就是"被压制的听牌要快走"的算术版本——不是脾气，是 `(B + f)/(P + 2B)`。

**牌局 1（`hand.01-06-flushdraw-two-questions`）— 单挑，翻牌 `Qh9h2s`，我方 `AhJh`，对手范围 `KdKc`。**

- 有位置（对手先行动）：你不需要在任何一条分支上先掏钱，未击中就便宜过牌，击中再决定。份额的兑现路径最短。

- 这一节拒绝给出"无位置打 0.8 折"这种数：`python -m pokergto` 的子命令列表是 `odds, mdf, equity, range, spr, icm, sizes`，没有任何一个返回 r。这个 0.8 是**未核验声明**，写在这里只是为了说明它不该被写成数字。

**牌局 2（`hand.01-06-dominated-checkdown`）— 翻牌 `Kh8c3d`，我方 `K9s`，对手范围 `KQo,KQs`，底池 6。**

- 对手下 3：需要 25.00%，你只有 16.6246%（纯赢 14.8485%，平分 3.5522%）。弃牌由名义胜率就决定，不用扯实现率。

顺带说清一个容易被误用的量：`pokergto.equity.vs_random` 能算"某个范围对一手随机牌"的胜率优势，也就是章节 03 的范围优势/坚果优势的原料。它是**蒙特卡洛**的，返回值里带 `iterations`、`seed` 与 `stderr`，输出会自报 `mc(n=20000,seed=...)`——它比实现率诚实得多，正因为它承认自己是抽样。抽样出来的份额仍然是份额，不是实现率。

## 为何成立、何时失效 / Why it works, when it breaks

**名义胜率在一种情况下就等于实现率**：钱已经关上。翻前全下被跟、河牌圈筹码进池之后，位置与后续行动线都不再能改变任何人能拿走的份额，`raw equity` 就是全部的现金期望。这是本节唯一一条"实现率与名义胜率相等"的陈述，而且它是从定义来的，不需要 `r`。

**其余情况都不相等**，因为下面这些结构性因素在移动 `r` 而不是移动份额：

1. **谁最后行动。** 最后表态者可以用一张免费牌兑现份额；先表态者要为同样的份额先付钱。
2. **能否便宜看到摊牌。** 份额集中在"我弃牌"的分支上时，实现率低；集中在"我看牌就好"的分支上时，实现率高。
3. **SPR。** 它决定钱能在什么价位关上：门槛 `SPR/(1+2·SPR)` 从 SPR 0.5 的 25.00% 涨到 SPR 19.5 的 48.75%。同一手牌的实现路径随 SPR 完全变形。
4. **压制关系。** 例 3 那手 `K9s`：份额低是算出来的，但它的低份额还额外带着"要再掏钱才能兑现"的结构，这是双重坏。
5. **多人底池。** 份额的兑现要和不在你控制里的行动线相乘，`07-01` 处理频率那一侧；实现率这一侧本仓库同样没有计算。

**本节失效之处**：如果有人告诉你某个场合的实现率是 80%，请问他三个问题——`r` 由哪个函数返回、在哪个测试里被核验、在哪个 `data/gen` 产物里带 provenance。今天的答案是"没有、没有、没有"。把这条空缺变成 `derived` 的路径写在 `ROADMAP.md` 的 M8：把胜率实现作为计算量而不是经验法则；具体做法需要一个翻牌后抽象研究（固定的行动线集合、可核验的 EV 拆解），而不是一个"我调出来的折扣表"。

## 陷阱 / Common mistakes

1. **用名义胜率付全下的价。** 拿 38.7187% 的 `Td9d` 去撞 SPR 19.5 的 48.75% 门槛，或者反过来用 SPR 0.5 的 25% 门槛为深筹码辩护。
   *代价*：例 2 的表已经把差距写成百分点：差 10.03 个百分点。用 `python -m pokergto spr --stack 97.5 --pot 5` 一分钟就能自查。
2. **把平分当赢。** `AcKd` 对 `AdKh` 的 97.0872% 是平分。
   *代价*：你以为五五开、准备全拿的钱，实际上一半都不属于"赢"这个分支。看 `equity` 输出的 `[W..../T....]` 拆解，别看合起来的百分数。
3. **把隐含赔率当免费。** `future_winnings` 的上界就是身后的筹码，而这条上界是可以算的（例：需要 3.67 才能打平，最多只有 3.25，于是最好的情况仍是 19.67% 需要量 > 19.15% 拥有量）。
   *代价*：在浅筹码里用深筹码的推理跟注，一年下来是稳定的净负。
4. **给实现率拍一个百分数然后当 `derived` 教。** "顶对打八折""同花听牌实现 85%"这类数字在仓库里没有来源。
   *代价*：这是本仓库存在的理由所要替换的东西——一个自信的、无出处的数字。要么标 **UNVERIFIED**，要么把它做进 M8。
