# 先推导再记忆：一个数字必须能被引擎重算出来

<!-- hands: 2 -->
<!-- terms: gto, nash-equilibrium, exploitability, best-response, provenance, unverified-claim, derivation-ref, minimum-defense-frequency, required-equity, indifference, multiway, icm, overbet, bet-size, fold-frequency, combos, bluff, spr -->

## 本节目标 / Objectives

- 在一分钟之内，从"纯诈唬必须无差别"这一条推出 `MDF = 底池 /(底池 + 下注)`，并用它现算一个你从没背过的尺度。
- 说清记忆的正确位置：推导**之后**的压缩产物，而不是推导的替代品；并说出这两者的区别在牌桌上值多少钱。
- 区分 `derived`、`reference`、`external` 三种来源，并解释一条标注为未核验的结论为什么可以留在课节里，而不必删掉。
- 指出记忆至少在三处会付出可量化的代价：尺度变了、人数变了、筹码换成钱的时候。

## 前置知识 / Prerequisites

- `00-01`：课节的分结构、AUTO 表块的来路、provenance 怎么读。
- 只需要会解一元一次方程。`02-01` 与 `02-02` 会在后面把这里用到的两条式子正式推一遍，
  `02-03` 是完整版；本节先让你尝到"自己推出来"是什么手感。

## 核心原理 / The principle

**可重算，是可核验的下限。** 一个数字如果能被一条命令在你的机器上重算出来，它就不需要任何人背书；
如果不能，你就只剩下"相信谁"这一个选项——而相信谁，正是这套教材要替换掉的东西。

于是每一条结论都必须能回答"你是怎么知道的"，并且答案要能落到三种之一：

- `derived`：本仓库 `src/pokergto/**` 里推出来或算出来的，带一个能点开的推导指针。
- `reference`：本仓库自己写的示意内容，只在"能被独立校验"的地方允许存在。
- `external`：外部来源，必须同时有 `upstream` 和一个登记在许可清单里的 `license`。

记忆不是被禁止的。被禁止的是**无源的记**：你有一个数，但没有通往它的路。

## 推导 / Derivation

先做那条最出名的结论，两行做完。设底池 `P`、对手新增下注 `B`，对手拿一手永远不可能赢的空气。

- 以概率 `f` 所有人都弃牌，空气白拿底池：`+P`。
- 以概率 `1 − f` 有人防守，空气输掉自己贴进去的钱：`−B`。

无差别（诈唬的期望值刚好为 0）：

```
f·P − (1 − f)·B = 0  ⟹  f = B/(P+B)  ⟹  MDF = 1 − f = P/(P+B)
```

到这里你已经有了整条曲线，不只是一个点。把同一条式子换个方向读，立刻得到三个"背不动"的东西：

```
防守配额（单挑）      MDF = P/(P+B)
每人防守配额（N 人）  d  = 1 − (B/(P+B))^(1/N)      ← N=1 时回退上式，这就是自校验
全下时的门槛          e  = SPR/(1+2·SPR)            ← 同一件事在 B=S 时的样子
```

第一条在 `src/pokergto/odds.py#minimum_defense_frequency`，第二条在
`src/pokergto/odds.py#defense_frequency_multiway`，第三条在 `src/pokergto/spr.py`，
三条都能被命令行当场跑出来。它们不是三条新知识，是同一条等式的三种代入。

再看记忆需要多少张表。尺度有 8 档、人数有 5 种、SPR 从 0.25 到 20 连续变化，
`data/gen/tables/table.02-03.mdf-vs-sizing.json` 的 8 行、
`table.07-01.multiway-defense` 的 20 行、`table.03-07.spr-commitment` 的 10 行——
把这些记下来是 38 个数字，而且它们只覆盖到表里有的那些组合：对手下 1.15 倍池底？底池 8 前面 3 个人？
一个都没背过。推导这边只有一个式子加一次代入，覆盖整条曲线。

最后一条，也是本节真正想让你带走的一条：**记忆在推导之后仍然有用，而且必须有**。
`P/(P+B)` 在牌桌上太慢了，你要在 15 秒内动。正确做法是自己推一遍，然后把常用的几档压成口头数
（1/3 池 → 75%、1/2 池 → 66.67%、底池 → 50%），把压缩后的表当缓存使用。区别在于：缓存可以被重置，
因为你知道它是怎么生成的；背来的表一旦被环境推出表外，就只能靠猜。

## 直觉 / Intuition

背下来的数像一张照片：拍得再清楚，也只覆盖取景框里那一小块。式子像画地图的规则，取景框外它照样画得出。

所以判断自己是在"推导"还是在"记忆"，有一个很土但有效的测试：**换个数字问自己**。
把 1/2 池换成 0.7 倍池底，把单挑换成三个人，把现金换成决赛桌。答案还能出来，你就拿着式子；
答案开始发虚，你就只拿着照片。

## 算例 / Worked examples

**例 1 — 背来的 66% 和推出来的 66.67%。** 半池：`P = 1, B = 0.5`。
`MDF = 1/1.5 = 0.6667`，命令行 `PYTHONPATH=src python -m pokergto mdf --pot 1 --bet 0.5` 打回 0.6667。
数值上你感觉两者一样。差别在于：背来的那个"66%"在 1/3 池上会被人脱口说成"大概七成就行"，
而 `odds` 表的 `1/3 pot` 行给的是 75.00%，不是 70%。差 5 个百分点。

**例 2 — 尺度一变，记忆就出表外。** 对手河牌超池下注 1.5 倍池底，`P = 20, B = 30`。

```bash
PYTHONPATH=src python -m pokergto mdf --pot 20 --bet 30
```

引擎回 `bet = 1.500 pot`，`MDF = 0.4000`。同一档在 `odds --lang zh` 的 `3/2 pot` 行里给出
跟注所需胜率 37.50%。现在算代价：一个只按"半池 25% 就跟"的习惯行事的人，会拿一副只击败 25%
对手范围的抓诈唬牌去跟这个 30。跟注后的池是 `20 + 2 × 30 = 80`：

```
0.25 × 80 − 30 = −10      而正确门槛 0.375 × 80 − 30 = 0
```

同一副底牌，同一张桌子，背错口径就是每跟一次输 10 个筹码。

**例 3 — 人数一变，方向都反了。** 三人底池（你是两个防守者之一），对手下 1/3 池：`P = 6.6, B = 2.2`。

```bash
PYTHONPATH=src python -m pokergto mdf --pot 6.6 --bet 2.2 --opponents 2
```

`d = 1−((2.2/8.8)^(1/2)) = 0.5000` 每人，合并仍是 0.7500，等于单挑那档的 MDF。
也就是说：**背来的单挑数字在这里会让你多防守**，每人 75% 而不是 50%。用引擎打印的那条式子手算一下
对手空气下注的期望：正确的 50% 各自防守时，两人都弃的概率 `0.5² = 0.25 = B/(P+B)`，
于是 `0.25 × 6.6 − 0.75 × 2.2 = 1.65 − 1.65 = 0`，诈唬刚好无差别——这正是推导的起点被验证了一次。
若两人都按 75% 防守，两人都弃只剩 `0.25² = 0.0625`，空气下注变成
`0.0625 × 6.6 − 0.9375 × 2.2 = 0.41 − 2.06 = −1.65`，也就是整桌多贴进去 18.75 个百分点的防守，
把对手的空气从"不赚不赔"打成"每诈唬一次白送 1.65"。

**例 4 — 筹码换成钱，门槛跳了一档。** 三人剩牌桌，筹码 5000 / 3000 / 2000，奖金 6000 / 3000 / 1500。
短码（2000）全下，筹码领先的我方要跟 2000，底池（含盲注 300）为 2300。

- 筹码口径：需要 `2000/4300 = 46.51%`，就是 `02-02` 那条所需胜率式子。
- 钱口径：跑三次 `icm`，拿到各分支的价值。`PYTHONPATH=src python -m pokergto icm --chips 5000,3000,2000 --payouts 6000,3000,1500`
  给赢家座位 4258.93；赢了之后的 `--chips 7000,3000 --payouts 6000,3000` 给 5100.00；
  输了之后的 `--chips 3000,3000,4000 --payouts 6000,3000,1500` 给我方 3342.86。
  解 `e × 5100 + (1 − e) × 3342.86 = 4258.93`，得 `e = 916.07/1757.14 = 52.13%`。

同一副底牌，同一堆筹码，一个决定，两个门槛：46.51% 和 52.13%。中间那 5.62 个百分点就是"筹码 ≠ 钱"的价格。
`table.12-03.icm-vs-chip-share` 把这整件事摊成 5 行：筹码占 37.50% 的座位只值奖金的 29.39%，
筹码占 6.25% 的座位值 10.86%。背下来的人记的是"短码别乱跟"，推出来的人知道贵在哪、贵多少。

## 实战牌局 / Live hands

EV 一律用单街近似：跟注的期望 = 击败概率 ×（底池 + 2 × 跟注额）− 跟注额。

**牌局 1（`hand.00-02-river-overbet-memory-fail`）— 单挑，河牌圈。**
牌面 `AsKd7h5c2s`，底池 20，对手下 30（1.5 倍池底）。我方抓诈唬牌，能赢的正好是对手范围里的空气。

- 决策点：跟 30，还是弃。
- 现算：`mdf --pot 20 --bet 30` → `bet = 1.500 pot`、MDF 0.4000；`odds --lang zh` 的 `3/2 pot` 行
  → 跟注所需胜率 37.50%、诈唬占比 37.50%。
- 判据：对手这个尺度的范围里空气必须超过 37.50% 才跟。
- 记忆派的做法：把河牌上"半池要 25%"的旧口诀搬过来，于是跟。跟注后的池 `20 + 60 = 80`，
  只击败 25% 的范围 → `0.25 × 80 − 30 = −10`。
- 推导派的做法：0.375 × 80 − 30 = 0 是边界，37.50% 以下就弃；我方这手达不到，弃。
- 错的代价：每犯一次 −10 个筹码。注意方向——**这里记忆不是"不够激进"，是过于激进**。

**牌局 2（`hand.00-02-three-way-defense-quota`）— 现金 6 人桌，翻牌圈三人底池。**
CO 开池 2.2bb，BTN 跟，BB 跟，底池 6.6bb。翻牌 `9h6d3c`，CO 下 2.2bb（1/3 池）。我方是 BTN。

- 决策点：弃、跟、加。我方底牌中等偏弱，本来就在配额边缘。
- 现算：`mdf --pot 6.6 --bet 2.2 --opponents 2` → 每人 0.5000，合并 0.7500。
  对照单挑那一档 `mdf --pot 6.6 --bet 2.2` → 0.7500。
- 判据：我只需要防守我范围的 50%，不是 75%。合并防守 75% 由三个人一起凑，不是我一个人扛。
- 记忆派的代价：按 75% 每人防守，两人都弃牌的概率掉到 `0.25² = 0.0625`，
  对手的空气从 0.000 变成 −1.65 每次；我多贴的那 25 个百分点几乎全是最弱的跟注组合，
  而它们正是在 `9h6d3c` 这种面上最容易被价值打的一档。
- 推导派的做法：留出 50% 的配额，把最弱的组合放在弃牌那一侧，另外两个人补上合并防守。
  这条规则的人数无关，N 换成 3、4、5 只要改一次代入。

## 范围图 / Range chart

导论课不发范围图：这一节的论点是"配额由式子给"，不针对某个具体范围。策略课里这一节放
`tools/gen_ranges.py` 生成的 `range.*` 图。举一个真实的例子读法：
`data/gen/ranges/range.02-03.mdf-floor-vs-half-pot.json` 的 `threshold` 是 0.66666667，
`total_combos` 是 884，`range_percentage` 是 66.67%，`provenance.kind` 是 `derived`，
`provenance.assumptions` 里明写了"按牌力从高到低填充，MDF 只约束总频率"。
那两句假设就是这个工件的全部秘密：884 个组合是配额，不是打法。

## 为何成立、何时失效 / Why it works, when it breaks

**成立的条件**：双方都会对对方的动作做反应；低于地板的防守会被惩罚；弃牌就是放弃底池；
筹码的效用是线性的（现金局近似成立）。

**推导本身也会失效的地方**，而且失效点是可指出的：

1. `d = 1 − (B/(P+B))^(1/N)` 假设各防守者**相互独立**。真实发牌里牌力移除会耦合两家范围，
   所以它是近似。本仓库把这条写进 `provenance.assumptions`，第 07 章用固定动作的三人模型把它往前推。
2. 防守方可以加注时，MDF 是对"跟或弃"推的下界；加注会替走一部分防守**动作**，
   但总防守配额那条地板不动。把" solver 里跟注频率低于 MDF"读成"可以少防守"是常见错。
3. 锦标赛里筹码不是钱（例 4）。低于 MDF 的防守可能才是最优，而这次是**推导换了目标函数**，
   不是记忆出错——这是第 12 章。
4. 对手不惩罚时，MDF 只是"不被剥削"的下界，不是"赚最多"的选择。对大众倾向的偏离属于第 13 章。
5. 时间不够时。这才是记忆的主场：把常用的那几档压成口头数当缓存，别在 15 秒里解方程。

## 陷阱 / Common mistakes

1. **把 `MDF` 当"跟注所需胜率"。** 前者 `P/(P+B)` 管范围配额，后者 `B/(P+2B)` 管单手牌。
   *代价*：例 3 那个局面上，`1/3 pot` 行的两个数是 75.00% 与 20.00%（单挑口径）。
   混用会得出"我只需要 20% 胜率，所以可以弃掉 75%"，方向整个反了。
   `mdf --pot 6.6 --bet 2.2` 与 `odds --lang zh` 各跑一次，一分钟就能拆干净。
2. **把记忆当结论，把推导当装饰。** 觉得自己反正"打的时候不会现算"，于是只背表。
   *代价*：例 2 那次 −10 个筹码，就是一次出表外的跟注；出表外时你手上没有式子，只能猜。
3. **看到 `UNVERIFIED` 就跳过，或者反过来把它当定论。** 两者都丢信息。
   *代价*：`NOTICE` 与 `adr/0005` 现在就把那条多人持续下注频率塌缩（常被写成单挑约 65%、
   三人约 30%、四人约 15%、五人及以下更低那一串）记为 `reference` + 未核验。
   跳过它，你在多人底池里没有模型；当定论用它，你在拿没人推过的数排范围。
   正确动作：读 `unverified_claims`，顺 `derivation_ref` 找可执行的符号，然后自己跑
   `mdf --pot 6.6 --bet 2.2 --opponents 2`，把 50.00% 每人 / 75.00% 合并这个**推出来的**结构拿去打底。
4. **按手牌类别估配额，不按组合数。** `data/gen/tables/table.01-01.combo-decomposition.json`
   写死了 4、6、12 三种每类组合数。
