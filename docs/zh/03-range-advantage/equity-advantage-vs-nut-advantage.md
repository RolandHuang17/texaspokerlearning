# 同一翻面上谁已经成顺子：用坚果优势而非胜率区分

<!-- hands: 2 -->
<!-- terms: range-advantage, equity-advantage, nut-advantage, the-nuts, capacity, range, equity, combos, board, flop, turn, bet-size, minimum-defense-frequency, bluff-to-value-ratio, bluff, value-bet, showdown -->

## 本节目标 / Objectives

- 能用两个范围的**成牌容量**解释坚果优势（nut advantage），并说出它能回答、而胜率优势（equity advantage）回答不了的那一类决策。
- 给定同一副公共牌与两个范围，能分别复算出胜率优势与坚果优势，并指出本节生成表里两列**方向相反**的那两行。
- 能说清这两个数各自的分母、参照点与失效条件，从此不把"我的范围更好"当成一句策略陈述。

## 前置知识 / Prerequisites

- `01-07` 读 13×13 网格：一格代表几个组合；本节的分母就是组合数，不是手牌类别。
- `02-04` 诈唬与价值的配比：尺度规定了价值与诈唬的比例，而比例的上半段必须有牌来填。
- `02-03` 最低防守频率：MDF 给出的是防守配额，它不判断配额由哪些牌支付。
- `01-02` 阻断牌与移除效应：理解"范围没有按公共牌收缩"这句话在指什么。

## 核心原理 / The principle

同一张牌面上，"谁的平均牌更好"和"钱推进去时谁站在最上面"是两个不同的数：

```
胜率优势 equity_edge = hero_equity − villain_equity        ← 谁能有**频率**地下注
坚果优势 nut_edge    = hero_nut_share − villain_nut_share   ← 谁能用**大尺度**下注
```

`hero_nut_share` 是 hero 范围里**处在当前两家范围所能达到的最高牌力层**的组合占比。它由 `pokergto.theory.range_advantage` 现算，是一条 `derived` 结论；两个范围本身是本仓库写下的示例输入，属于 `reference`。

## 推导 / Derivation

把符号先定义完，再写等式。`H` 与 `V` 是两个范围，`w_i` 是组合 `i` 的权重（示例范围里全是 0 或 1），`B` 是公共牌。

**胜率**是对所有河牌结果的平均。翻牌圈 `B` 有 `|Ω| = 1176` 个补全（`runout_boards(B)` 现算，等于 `C(49,2)`）：

```
hero_equity = Σ_{ω∈Ω} Σ_{i∈H} Σ_{j∈V} w_i w_j · ½·1[s_i(ω)=s_j(ω)] + 1[s_i(ω)>s_j(ω)]
              ─────────────────────────────────────────────────────────────────────────
              Σ_{ω∈Ω} Σ_{i∈H} Σ_{j∈V} w_i w_j · 1[i 与 j 不共用同一张实体牌]
```

分母里那句"不共用同一张实体牌"是关键：`range_equity` 在穷举时**剔除了**与公共牌或对手牌冲突的组合，所以它是一个以牌面为条件的量。

**坚果占比**根本不走 `Ω`。它只看当前牌面：

```
T   = max( max_{i∈H} s_i(B), max_{j∈V} s_j(B) )         ← 两家范围内目前能达到的最高分
share(H) = Σ_{i∈H, s_i(B)=T} w_i / Σ_{i∈H} w_i
nut_edge = share(H) − share(V)
```

两个式子有三处结构性差异，它们就是本节的全部论点：

1. **是否积分过未来牌**：胜率对 1176 张河牌取平均，坚果占比只看此刻。
2. **比较对象**：胜率是 i 与 j 的**成对比较**，坚果占比是与一个**绝对参照分 T** 的越级判断；越级是 0/1，平均是连续值。
3. **分母**：胜率除的是**发得出来**的成对组合，坚果占比除的是范围**按牌面收缩之后**的组合数。`advantage` 先收缩再取顶，所以 `Kh7s3d` 上 hero 的分母是 44（移除 `Kh`、`7s`、`3d` 之后剩下的），不是 spec 写出的 52。

第三步是本节曾经真正算错的地方，所以修法是一道拒绝，而不是一条脚注。分子只数合法组合、分母却数 spec 写出的全部组合，得到的占比会偏小，而且偏小的幅度看起来完全不像错误：`Kh7s3d` 上 `77` 是 6 个组合，其中 3 个用了牌面已经发出的那张七。空范围从一开始就会大声失败（`InputError("both ranges need combos")`）；现在含不可能组合的范围也会同样失败，因为 `nut_advantage` 与 `is_capped` 都会调用 `_assert_board_excluded`。本章由此确定一条口径：**下面每个占比除的都是合法组合数，纸面组合数只在括号里出现。**

由定义立刻得到一件重要的事：**`equity_edge` 与 `nut_edge` 互相不蕴含**。`equity_edge > 0` 不要求 `nut_edge > 0`，因为前者是平均、后者是尾部。下面 4 个算例里第 2、3 行就是两个方向的反例，而生成表的 `checks` 里专门有一条 `edges_disagree` 断言"至少有一行两列方向相反"——如果一行都不相反，这张表存在的理由就没了。

## 直觉 / Intuition

胜率优势是**水面的高度**，坚果优势是**谁站在屋顶上**。

- 水面高，说明随便一次碰瓷式的小注你都占便宜：它管"下不下、下多频繁"。
- 屋顶高，说明当筹码真的推进到底、有人敢加注时，你手里有牌能跟到底：它管"最大能下多大"。
- 一个尺度越大，它就越是在向"被加注"下挑战书；而对抗加注的唯一保险，就是你的范围里确实存在最上层那几手牌。`02-04` 里 2 倍池底要求价值 : 诈唬 = 1.5 : 1，那"价值"两字要靠屋顶上的牌来兑付，不是靠平均水位。

心智模型：拿着 `table.03-01` 的两列去读一个局面——**先看两列是否同向**。同向时你只需要决定尺度；反向时你必须把"频率"和"尺度"拆成两个独立问题，任何一个笼统的"我这范围更强"都会答错其中一半。

## 算例 / Worked examples

以下四行都由 `advantage(hero, villain, board, mode="exact")` 现算，穷举、无抽样误差。复算命令写在每行末尾。

**例 1 — 干高面 `Kh7s3d`（hero = CO 开池，44 个合法组合、纸面 52；villain = BB 跟注，合法 58、纸面 64）。**
hero 胜率 71.5272%，胜率优势 **+43.0545%**；两家范围内目前最高分是三条 7（`77`，牌面上的 `7s` 让 6 个组合只剩 3 个），所以 hero 坚果占比 3/44 = **6.8182%**，villain 为 0，坚果优势 **+6.8182%**。两列同向：hero 既能常下注，也能下大注。
同一层牌若除回 spec 的纸面分母，读到的是 6/52 = 11.5385%——这正是这张表最初发布过的数，也是 `table.03-01` 现在不再打印的数。
复算：`python -m pokergto equity "AKs,AQs,ATs,KQs,AKo,AQo,99,77" --range-villain "KJs,QJs,JTs,T9s,98s,A5s-A2s,KQo,AJo,76s" --board "Kh7s3d" --json`（输出 `"equity": 0.715272`，与生成表逐位相同）。

**例 2 — 低连张面 `9h6d3c`（hero = BTN 开池，合法 63、纸面 66；villain = BB 跟注，合法 48、纸面 60）。**
hero 胜率只有 36.8154%，胜率优势 **−26.3691%**：平均意义上 hero 大幅落后。但当前最高分是三条 9（牌面有 `9h`，`99` 的 6 个组合只剩 3 个，且都在 hero 手里），villain 收缩后的 48 个组合里没有三条 9 → hero 坚果占比 3/63 = **4.7619%**，坚果优势 **+4.7619%**。
**落后的一方握着屋顶。** 频率那一列说 villain，尺度那一列说 hero——这正是 `can_bet_often = villain` 与 `can_bet_big = hero` 两格不同的那一行。
除回纸面的 66，同一层牌读到 6/66 = 9.0909%，这就是第 3 条差异的两个答案里的第二个。

**例 3 — 双色带同花听牌面 `As9s5d`（hero = CO 开池，合法 46、纸面 54；villain = BB 跟注，合法 29、纸面 36）。**
hero 胜率 61.0233%，胜率优势 **+22.0466%**；而当前最高分是三条 9（牌面有 `9s`，`99` 只剩 3 个组合），这 3 个组合**全在 villain 手里**：hero 坚果占比 0.0000%，villain 3/29 = 10.3448%，坚果优势 **−10.3448%**。
例 2 的镜像：领先的一方没有屋顶。这一行的 `can_bet_often = hero`、`can_bet_big = villain`。
除回 villain 纸面的 36，同一层牌读到 6/36 = 16.6667%。

**例 4 — 同一个翻牌的转牌 `Kh7s3d4c`（hero 合法 40、纸面 50；villain 合法 44、纸面 48）。**
胜率优势 **+53.9550%**，坚果优势 **+7.5000%**（最高层是三条 7：`7s` 在牌面上，`77` 的 6 个组合只剩 3 个，hero 的 40 个合法组合 → 3/40；除纸面分母则是 6/50 = 12.0000%）。
这一行**不是**例 1"发了一张牌之后"的结果：转牌的两个范围是重新写过的示例输入（`44` 进来了，`KQs` 之外的组合也换了）。把例 4 与例 1 直接相减当作"一张牌的边际影响"，是一个本节没有依据、也不该被读出的推论。街与街之间怎么连起来，是 `03-03` 的主题。

## 实战牌局 / Live hands

**牌局 1（`hand.03-01-low-connected-flop`）— 6 人桌，盲注 0.5/1。BTN 开池 2.2 bb，BB 跟 1.2 bb，底池 2.2 + 1 + 1.2 = 4.4 bb。翻牌 `9h6d3c`。**

范围就是例 2 的两个示例输入：BTN 63 个组合，BB 48 个组合。BTN 的坚果占比 4.7619%，BB 为 0；BTN 胜率 36.8154%。

- **决策：BTN 该用 1/3 池底还是 2 倍池底 8.8 bb？** 现算：1/3 池底 1.47 bb 需要 `f* = 0.250426` 的弃牌率、给 BB 的 `MDF = 0.749574`、跟注所需胜率 0.200272；2 倍池底 8.8 bb 需要 `f* = 0.666667`、`MDF = 0.333333`、跟注所需胜率 0.400000（`python -m pokergto mdf --pot 4.4 --bet 1.47` 与 `--bet 8.8`）。
- **BTN 的 2 倍池底按 `02-04` 的无差别比例配好**：价值 = `99` 的 3 个合法组合（纸面 6 个，`9h` 在牌面上），诈唬 = `AJs` 四个组合里的两个，3 : 2 = 1.5 : 1，正好是 2 倍池底要求的比例（`value_to_bluff_ratio` 现算 2 倍池底为 1.5）。挑哪两个 `AJs` 是自由的——本仓库没有任何产物替你做这个选择，比例也不关心。
- **BB 该怎么应？** 现算 BB 三个片段对 BTN 这个下注范围在 `9h6d3c` 上的胜率：`T9s,98o,97o,66,55`（合法 30 个组合、纸面 40）= **56.0624%**，远高于 40%；`87s,76s,65s,54s,T8s`（合法 18、纸面 20）= **39.4966%**，比 40% 差 0.5034 个百分点；整条 48 个合法组合 = **48.9628%**。所以 MDF 要的 33.33%（48 个里 16 个）BB 轻松付得起，而且付的方式是"用那 30 个组合去跟"，不是"用听牌去跟"。
- **错案的代价**：BTN 若因为"我只领先 4.76%、对手平均比我强 26.37%"就不敢用 2 倍池底，等于把屋顶那一列丢掉；BB 若反过来把 30 个能跟的组合全弃掉，每手弃掉的期望是 `ev_call(4.4, 8.8, 0.560624) = **+3.5337 bb**`，30 个组合合计 **106.01 bb**——这是本节最容易付的一笔钱。而用 18 个听牌组合去跟则是每手 **−0.1107 bb**：刚好差一点，"差一点"本身就是内容。

**牌局 2（`hand.03-01-two-tone-flush-flop`）— 同一桌，CO 开池 2.2 bb、BB 跟 1.2 bb，底池 4.4 bb。翻牌 `As9s5d`。**

范围比例如例 3：CO 46 个组合、胜率 61.0233%；BB 29 个组合、坚果占比 10.3448%（`99` 剩下的 3 个组合）。`can_bet_often = hero`、`can_bet_big = villain`。

- **决策：CO 要不要用 2 倍池底 8.8 bb 把频率优势变现？** 2 倍池底要求 BB 的防守降到 MDF = 0.333333（`python -m pokergto mdf --pot 4.4 --bet 8.8`）。但 CO 在 BB 的三条组合之上**一个都没有**——BB 那 6 个合法的三条组合（`99` 与 `55`，纸面 12 个，占 BB 合法范围 6/29 = 20.69%）。
- **被加注的算术**：BB 用这 12 个组合全押加注（再加 17.6 bb），此时底池 4.4 + 8.8 + 8.8 = 22.0 bb，CO 要跟 17.6 bb，所需胜率 `17.6/(22 + 35.2) = 0.307692`；而 CO 的整条范围（46 个合法组合）对 `99,55` 只有 **6.4625%** 胜率。期望 `ev_call(22.0, 17.6, 0.064625) = **−13.9035 bb**` 每次；弃牌只损失已经推进去的 8.8 bb。
- **结论**：CO 的下注尺度上限由 `nut_edge` 那一列定住。频率（1/3 池、`f* = 0.250426`）照用，尺度别碰 2 倍池底——不是因为"对手可能很强"，而是因为 CO 范围内**没有任何组合**站在 BB 加注范围之上，这一句可以逐组合复算。

## 为何成立、何时失效 / Why it works, when it breaks

**成立的前提**：两个范围是你实际面对的分布（不是"他可能拿什么"）；比较用组合数加权；评估器对每个组合给出同一套全序。这三条都在 `pokergto` 里，所以两列都是 `derived`。

失效或需要打折的地方：

1. **不完整的牌面上，坚果优势系统性低估听牌一方。** `nut_advantage` 的参照是"现在能达到的最强牌"，不是"所有发展牌序之后能达到的最强牌"。生成表的 `caption` 与 `pokergto/theory/range_advantage.py` 的 docstring 都写了这条。用牌面扫描量一下它的量级：`9h6d3c` 上 BTN 的坚果占比 4.7619%、BB 为 0；把牌堆里剩下的 49 张牌逐张代入，**19 张**（`2`、`5`、`6`、`7`、`T` 的花色）会把最高层交给 BB，其余 30 张仍在 BTN 手里。再把 49 × 48 = 2352 条转牌+河牌路线全部代入（每条路线都把两个范围重新按牌面收缩）：**BTN 在 1256 条路线（53.4014%）末了握着最高层**，BB 是 1148 条（48.8095%）；两个数不是互补事件——有 52 条路线两边各有一个组合并列在顶上，所以它们相加会超过 100%。所以"BB 坚果占比 0"的正确读法是"BB 现在 0"，不是"BB 这条线没有坚果"。街与街怎么衔接属于 `03-03`。
2. **每个占比都是"对合法组合"的比，所以只有用同样的收缩才复算得出来。** 例 1 到例 4 若改除 spec 的纸面组合数，就得到 11.5385%、9.0909%、16.6667%、12.0000%——每一个都被抬高了，因为分母里含着一张 `7h7s` 这类牌面已经发掉的手。`nut_advantage` 与 `is_capped` 拒绝的正是这种输入，而 `table.03-01` 把每行的 spec 一起公布，分母随时可查。所以 6.8182% 要读成"这个范围真能持有的 44 个组合里有 3 个"，不要读成"对手有 6.82% 的概率拿着三条 7"。
3. **`T` 是两家范围的最高分，不是牌面的可达上限。** `Kh7s3d` 上两列的参照是三条 9，而这张牌面真正能达到的最强牌是三条 K（`KK`）。所以"hero 有坚果优势"是一句**相对**结论；相对牌面上限而言两边都可能是封顶的。这正是 `03-02` 要拆开讲的那对概念（`nut_advantage` 对 `is_capped`）。
4. **`near_nuts` 参数在本节没有用处。** `nut_advantage(..., near_nuts=k)` 的"步"是评估器全序里的**整数刻度**，不是"一种牌型"。现算：三张牌的牌面下，`Kh7s3d` 上两个相邻不同牌型之间最小间隔 16 个单位，三条 9 与三条 K 之间相差 368,640 个单位；`k = 0,1,2,3` 四档算出的坚果占比全部一样。别指望它替你定义"次坚果"。
5. **胜率优势假设全下到摊牌。** 它是 all-in equity，不含"后面街会被打过"的折价，即 `01-06` 的胜率实现问题。频率那一列的可信度取决于这条。

## 陷阱 / Common mistakes

1. **只凭胜率优势就上大尺度。** 例 3 的 CO 领先 22.0466% 却握 0 层屋顶。
   *代价*：牌局 2 算过——被 `99,55` 这 12 个组合全押加注后跟注的期望是 **−13.9035 bb** 每次，而正确弃牌只损失 8.8 bb；也就是说多出来的 **5.1035 bb** 完全是"把频率当成容量"的账单。
2. **把坚果占比为 0 读成"这条线没有牌"。** 例 2 的 BTN 坚果占比 4.7619%、BB 为 0，但 BB 有 63.1846% 胜率；反过来说，BTN 的那 3 个组合只在 49 张转牌里的 30 张之后仍在最高层。
   *代价*：弃掉那 30 个能跟的组合，等于每手放弃 **+3.5337 bb** 的跟注期望、合计 **106.01 bb**；这是"配额付了，但用错误的牌付"的镜像错误。
3. **跨表做算术。** `table.03-01` 与 `table.03-02` 在 `9h6d3c` 上**故意共用**同一份 villain spec（生成表的 `checks` 里有一条专门断言这件事）。真正会咬人的差别在产物与本节的示例之间：`03-02` 的例 3 去掉了 `97o`，于是它量的是纸面 48 个组合，产物量的是纸面 60 个。
   *代价*：同一句"BTN 对 BB"的 villain 胜率，产物那份范围是 63.1846%、例 3 那份是 61.2680%，差 **1.9166 个百分点**；拿一份范围的坚果组合数去除另一份的分母，得到的数没有任何产物支持。每张表都要读它自己的 `spec`。
