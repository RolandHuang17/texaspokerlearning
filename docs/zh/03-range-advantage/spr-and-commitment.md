# SPR：把筹码深度与底池尺寸压成同一个数

<!-- hands: 2 -->
<!-- terms: spr, effective-stack, shove, required-equity, pot, bet, call, fold, equity, combos, dead-money, line, break-even-percentage, short-stack, generated-artifact, derivation-ref -->

## 本节目标 / Objectives

- 给任意一条行动线，能算出某个决策点开局的 SPR = 身后筹码 / 底池，并说清死钱算不算进底池会怎样改变这个数。
- 能从"全下被跟注时我拿到的份额必须不小于我投进去的钱"这一条独立推出 `SPR/(1+2·SPR)`，而不是背下它。
- 能用这条阈值判断一手牌（胜率由引擎穷举算出）在当前深度是否值得套池，并解释为什么阈值的上限是 50%、而胜率高于 50% 的牌在任何深度都可以全下。

## 前置知识 / Prerequisites

- `02-06` 一套符号管住所有动作：`pot` 指行动者加注**之前**底池里的钱，`bet` 指行动者要加的钱；全下只是 `bet = 身后筹码` 的特例，本节的公式就是它代入后的结果。
- `01-07` 读 13×13 网格：SPR 不改变任何范围的组合数，它改变的是"哪些组合值得把钱推出去"这条界线，所以两节要用同一套组合数加权。

## 核心原理 / The principle

一条街开始时的筹码底池比（SPR）定义为

```
SPR = 身后有效筹码 S / 底池 P
```

把整个身后筹码全下（shove）所需要的胜率是

```
e* = S / (P + 2S) = SPR / (1 + 2·SPR)
```

它是 `derived` 结论：只用了"钱要能挣回来"这一个条件，不含任何范围表、任何求解器、任何人的经验。它的值域是 `(0, 1/2)`，随 SPR 单调上升并在 `SPR → ∞` 时逼近 `1/2`。

## 推导 / Derivation

底池 `P`（包含死钱），你身后 `S`，对手身后至少 `S`。你全下、被跟注，最终底池是 `P + 2S`，你在里面的份额是 `e·(P + 2S)`。要求这个份额不小于你冒的风险 `S`：

```
e·(P + 2S) ≥ S
e ≥ S / (P + 2S)                                ← 用绝对筹码写
e ≥ (S/P) / (1 + 2·S/P) = SPR / (1 + 2·SPR)      ← 同一条式子除以 P
```

第二步只是分子分母同除 `P`，**它要求 `P > 0`**：这一步就是全节唯一可能失败的地方。`pokergto.spr.spr` 在 `P ≤ 0` 时抛 `SPR needs a positive pot`，这不是防御性代码，是在告诉你"底池为零时深度没有意义"——一条谁都没投钱的线里，SPR 是无穷大而不是任何数。

值域也来自同一条式子，不需要新的假设：

```
lim(SPR→∞) SPR/(1+2·SPR) = 1/2      且     SPR/(1+2·SPR) < 1/2 恒成立
```

因为分母 `1 + 2·SPR` 总是比分子的 `2·SPR` 多出那个 `1`。**所以任何胜率 ≥ 50% 的牌在任何深度都够全下**，而任何胜率 < 50% 的牌都存在一个"太深、不能全下"的 SPR。反函数把这句话变成可算的数：

```
SPR* = e / (1 − 2e)          ← 胜率 e 恰好允许全下的最大 SPR
```

`e = 1/2` 时分母为零，反函数发散——引擎在这里会直接抛 `ZeroDivisionError`，这正是上限存在的算术证据，而不是措辞。

## 直觉 / Intuition

SPR 回答的是"**这条线还剩几次全下**"：SPR = 1 意味着底池和你的筹码一样大，一次下注就能把后面所有的决策做完；SPR = 15 意味着底池只是一小块，剩下的钱还要经过好几条街才动得了。

于是"顶对能不能套池"这个问题被拆掉了：它不再是一个要背的表，而是两个数的比较。

- 阈值只随 SPR 变：同一个 `SPR = 5` 在 6bb 底池和 60bb 底池里是同一条线（下一节的表把这一点直接算给你看）。
- 深度改变的是**门槛**，不是你的牌：底池下注时你的胜率不会因为筹码变厚而改变。
- 上限 50% 是关键的心理模型：只要你的牌是 favorite（胜率高于对家），"太深所以不能全下"这件事在数学上不存在。

心智模型：SPR 是杠杆比率，阈值是这条杠杆撬动一次全下所需要的最小力气。

## 算例 / Worked examples

以下每个数都是本节列出的命令产生的，`equity` 一律来自精确穷举（`exact: true`，无抽样误差）。

**例 1 — 尺度不变性。** `python -m pokergto spr --stack 60 --pot 12` 给出 `SPR = 5.000`，全下需要 `0.4545`（精确值 `5/11 = 45.4545%`）。同一命令换成 `--stack 30 --pot 6`、`--stack 15 --pot 3`、`--stack 120 --pot 24` 都得到 `5.000` 与 `45.4545%`。**四个看起来完全不同的局面是同一个局面**，这就是 SPR 存在的全部理由。

**例 2 — 四条真实行动线。**（100bb 深度按 100 计，盲注 0.5/1 记为死钱并计入底池）

- 100bb，CO 开池 2.5 / BTN 跟注：`S = 97.5`，`P = 6.5` → SPR `15.0000`，全下需要 `48.3871%`（精确 `15/31`）。
- 100bb，CO 2.5 / BTN 3-bet 7.5 / CO 跟：`S = 92.5`，`P = 16.5` → SPR `5.6061`，需要 `45.9057%`（`185/403`）。
- 25bb，同一条 3-bet 线：`S = 17.5`，`P = 16.5` → SPR `1.0606`，需要 `33.9806%`（`35/103`）。
- 10bb，CO 2.2 / BTN 3-bet 6.5 / CO 跟：`S = 3.5`，`P = 14.5` → SPR `0.2414`，需要 `16.2791%`（`7/43`）。

这四行分别由 `python -m pokergto spr --stack 97.5 --pot 6.5`（打印 `15.000 / 0.4839`）、`--stack 92.5 --pot 16.5`（`5.606 / 0.4591`）、`--stack 17.5 --pot 16.5`（`1.061 / 0.3398`）、`--stack 3.5 --pot 14.5`（`0.241 / 0.1628`）产生；括号里的精确分数由 `python -c` 调 `pokergto.spr.all_in_equity_needed(pot, stack, exact=True)` 得到。

**例 3 — 死钱改变阈值。** 同一条 100bb 3-bet 线，若底池只算两家投入的 `7.5 × 2 = 15`（丢掉 1.5bb 死钱），`spr(92.5, 15) = 6.1667`，阈值升到 `46.25%`；算上死钱是 `5.6061` 与 `45.9057%`。差 0.34 个百分点，看起来小，但**结论可能因此翻转**：胜率 46.0% 的牌在一种记法下够、在另一种下不够。这不是舍入问题，是约定问题，所以本仓库把约定写死在句子开头："底池含死钱"。

**例 4 — 阈值与手牌胜率对撞。** `python -m pokergto equity "9d7d" "AA,KK,QQ,JJ,TT,AKo,AQo,ATo,KQo,AJs" --board "Th8s2c"` 给出 `0.395521`（39.5521%）。这条两头顺听牌：

- 在 SPR `1.0606`（25bb 线）够全下：需要 33.98%；
- 在 SPR `5.6061`（100bb 3-bet 线）不够：需要 45.91%；
- 在 SPR `15.0`（100bb 单加注池）更不够：需要 48.39%。

同一手牌、同一张牌面、同一个下注尺度，只有筹码厚度不同——**这是"SPR 决定承诺"这句话唯一可核验的形式**。

**例 5 — 上限 50% 是活的。** `python -m pokergto equity "Ah4h" "KK,QQ,JJ,TT,AKo,AQs,KQs" --board "9h5d2h"` 给出 `0.571768`。57.18% > 50%，所以它在 `SPR = 0.2414 / 1.0606 / 5.6061 / 15.0 / 20.0 / 100.0` 每一个深度都够全下（对应阈值 `16.28% / 33.98% / 45.91% / 48.39% / 48.78% / 49.75%`）。反过来说，`python -m pokergto equity "Jd9d" "AA,KK,QQ,JJ,TT,AKs,AQs,ATs,KQs,AKo,AQo" --board "Kh7s3d"` 的 `0.152320` 在任何 SPR ≥ 0.2414 的深度都不够全下——10bb 短码（16.28%）救不了它。

**例 6 — 跟注阈值 ≠ 套池阈值。** 100bb 3-bet 池，BTN 下 5.5 进 16.5：跟注一级需要 `5.5/(16.5+11) = 20.00%`，而把身后 92.5 全下需要 `92.5/(22 + 2·92.5) = 44.6860%`（对手那 5.5 已经算进底池，所以比起点的 45.91% 略低）。`9d7d` 的 39.55% 落在两者之间：跟注的期望是 `ev_call(16.5, 5.5, 0.395521) = +5.3768` 筹码，全下的门槛还差 5.13 个百分点。

## 实战牌局 / Live hands

**牌局 1（`hand.03-07-openender-two-depths`）— 两头顺听牌在两种深度里的两个答案。**

座位与钱：6 人局，第一条线所有人 100bb，第二条线所有人 25bb。CO 在两条线里都用 `9d7d` 跟注 BTN 的 3-bet。翻牌都是 `Th8s2c`。

- 100bb 线：底池 `16.5`（含 1.5 死钱），双方身后 `92.5` → SPR `5.6061` → 全下需要 **45.9057%**。BTN 下 5.5。`9d7d` 对 BTN 声明的下注范围 `"AA,KK,QQ,JJ,TT,AKo,AQo,ATo,KQo,AJs"` 的胜率是 **39.5521%**。决策：**跟注，不全下**。跟注的期望 `ev_call(16.5, 5.5, 0.395521) = +5.3768`；若改成全下 92.5 进 22，门槛是 44.6860%，比手里的胜率还差 5.13 个百分点，多推的 87 个筹码买不到它需要的胜率。
- 25bb 线：底池同样是 `16.5`，双方身后 `17.5` → SPR `1.0606` → 全下只需要 **33.9806%**。同一手 39.5521% 的牌**已经超过门槛 5.57 个百分点**。决策：**全下**。此时"跟注保留变化"是亏的：跟注只是把同一个决定推迟到转牌，而推迟的代价是把 33.98% 的低门槛换成转牌更高的门槛。
- 这一对牌局里没有一句话关于对手的风格：差别全部来自 `17.5/16.5` 与 `92.5/16.5` 这两个除法。

**牌局 2（`hand.03-07-adkc-two-lines`）— 顶对两张牌面之外的第三维：深度。**

座位与钱：40bb 线，CO 拿 `AdKc` 开池 2.5，BTN 3-bet 到 7.5，CO 跟。翻牌 `Kh7s3d`，底池 `16.5`，CO 身后 `32.5` → SPR `1.9697` → 全下需要 **39.8773%**。

- `AdKc` 对 BTN 声明的 3-bet 下注范围 `"AA,KK,QQ,JJ,TT,98s,AKs,AQs,AKo,AQo"` 的胜率是 **79.4731%**（`python -m pokergto equity "AdKc" "AA,KK,QQ,JJ,TT,98s,AKs,AQs,AKo,AQo" --board "Kh7s3d" --json`）。79.47% ≫ 39.88%，所以这条线从翻牌开始就只有一个动作：把钱推进去。BTN 下 5.5 时，`ev_call(16.5, 5.5, 0.794731) = +16.3551` 筹码，弃牌等于把这一整个数额扔掉。
- 同一条 3-bet 线换成 100bb：SPR `5.6061`、门槛 `45.9057%`——79.47% 仍然远超，结论不变。结论不变本身就是这一节要教的：**"顶对要不要套池"从来不是顶对的问题，是 SPR 的问题；只有当手牌胜率落在两个阈值之间时（牌局 1 的 39.55%），深度才第一次成为决定因素。**

## 为何成立、何时失效 / Why it works, when it breaks

**成立需要的前提**，逐条写清楚：

1. **筹码的效用是线性的。** 现金局成立；锦标赛接近钱圈时不成立，那时正确的门槛是 ICM 定价后的，比本节阈值高（第 12 章）。
2. **全下就是打到摊牌。** 公式假设钱进去之后没人能弃牌。如果对手可能对你的全下弃牌，你的全下就多了诈唬成分，正确的工具换成 `pokergto.ev.break_even_equity_to_bet`（第 `04` 章）。
3. **喂进阈值的胜率是真实胜率。** 这是最容易失守的一条，而且引擎会直接推翻口诀：`python -m pokergto equity "AhKh" "7c7d" --board "7s6d2c" --json` 给出 **0.000000**（990 个转牌+河牌组合里，两高张一次都没赢）。"两高张有 6 张补牌、约 24%" 讲的是对**一个对子**，不是对**三条**：对三条时你配对只得到对子，而三条已经在赢你。牌面一换就变了：同一手牌在 `7h6s2c`（两色）上是 **0.028283**，因为对手多了"转牌与河牌都得是红桃"这种后门同花。
4. **SPR 是快照，不是线的属性。** 底池每进一次钱，阈值就下降：100bb 3-bet 池起点 SPR `5.6061`（门槛 45.9057%），CO 跟了 1/3 池下注之后是 `spr(87.0, 27.5) = 3.1636`（门槛 **43.1762%**），而对手的 5.5 已经躺在中间时你全下的门槛是 44.6860%。第三个数比第一个低、又比第二个高，因为它的 `P` 与 `S` 来自不同的时刻——**同一手牌，三个门槛，全都正确，全都可算**（例 6）。

**失效/需要改写的情形**：多人底池里"全下"含义改变，因为你要一次打赢两家，`e` 不再是二家摊牌的胜率而是每家胜率的乘积结构（见 `07-01` 与本卷 `03-09`）；有前置下注与再加注可选时，跟注频率与套池频率可以分离（`02-03` 已经讲过配额与手段的区别）；牌面有坚果容量差异时，同样 39.55% 的胜率在"对手能有的最强牌"不同的两条线里价值不同（`03-01`）。

## 陷阱 / Common mistakes

1. **把 SPR 当成翻牌前算一次就够的数。** SPR 属于决策点，不属于行动线。同一条 100bb 3-bet 线里它从 `5.6061` 掉到 `3.1636`（1/3 池下注被跟之后），阈值从 45.9057% 掉到 43.1762%。用起点的门槛去判断转牌的全下，你会系统性地把胜率落在 43.18%–45.91% 之间的那批牌弃掉——而这一段区间不是空的：`python -m pokergto equity "9d7d" "AKo,AQo,KQo,ATo" --board "Th8s2c" --json` 给出 **44.4242%**，正好落在 43.1762% 与 45.9057% 之间——拿起点的门槛判它该弃，拿跟注之后那条街的门槛判它该全下，两者只差一次除法。
2. **背"顶对可以套池 / 听牌不能套池"这类口诀。** 反例就是本节算例 4：`9d7d`（听牌）在 SPR 1.0606 是全下、在 SPR 5.6061 是跟注，`Ah4h`（也还是听牌）在 SPR 100 都是全下。*代价*可以精确算：在 SPR `1.0606` 那一条线里弃掉 `9d7d` 等于放弃 `ev_call(16.5, 5.5, 0.395521) = +5.3768` 筹码每手；把同一手牌放进 SPR `15.0` 的单加注池（`python -m pokergto spr --stack 97.5 --pot 6.5`）里全下，门槛是 48.3871% 而手里的胜率是 39.5521%，等于买了一份比自己弱 8.83 个百分点的保险。
3. **用"跟注所需胜率"替代"套池所需胜率"。** 在同一局面里 1/3 池下注的跟注门槛是 20.00%，全下门槛是 44.6860%（或起点 SPR 的 45.9057%）。*代价*：`Jd9d` 对 `"AA,KK,QQ,JJ,TT,AKs,AQs,ATs,KQs,AKo,AQo"` 只有 15.2320%，`ev_call(16.5, 5.5, 0.152320) = −1.3112` 筹码——它连跟注的门槛都没过；而把它当"听牌所以便宜跟"打，等于在两条街上重复这个负期望，直到 SPR 逼你把 92.5 推进去。

## 练习 / Drills

先手算，再用命令核验；每条答案都是本节产生过的数。

- 100bb、CO 开池 2.5 / BTN 跟注、死钱计入：SPR 与全下门槛？（`python -m pokergto spr --stack 97.5 --pot 6.5` → SPR 15.000，门槛 48.3871%）
- 4-bet 池：BTN 3-bet 7.5、CO 4-bet 18.5、BTN 跟，100bb → `spr(81.5, 38.5) = 2.1169`，门槛 40.4467%。门槛比 3-bet 池低了多少个百分点？（45.9057% − 40.4467% = 5.46 个百分点）
- 反推：一手牌在 SPR 3 时恰好够全下，它的胜率是多少？（`all_in_equity_needed_from_spr(3) = 0.428571`，即 42.8571%）
- 上限检验：`all_in_equity_needed_from_spr(1000)` = 0.499750，仍 < 1/2。用 `python -c` 试 `e = 1/2` 的反函数，观察 `ZeroDivisionError`，并解释它为什么是定理而不是 bug。
- 口诀检验：`python -m pokergto equity "AhKh" "7c7d" --board "7s6d2c" --json` 为什么是 0？把牌面改成 `7h6s2c` 再算一次（0.028283），说出这两个数各由什么牌型可能撑起。
