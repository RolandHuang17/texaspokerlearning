## 本节目标 / Objectives

- 能把 Kuhn 一个信息集的账本从第 1 轮推到第 8 轮，并说清频率怎么跟着账本走。
- 能读出本仓库那份生成物（`data/gen/solver/kuhn.json`）的 12 行频率，并复述它到底收敛到了什么。
- 能解释"头牌只下注约 64%"为什么不是 bug：给出让它成立的无差别条件，并验证它满足这个条件。
- 能说清 `solver/proofs.py` 为什么断言占优关系与族的边界，却不断言开注频率——以及这教你怎么读任何求解器的输出。

## 核心原理 / The principle

Kuhn 是本章唯一"每一步都能手算"的博弈：3 张牌、单街、下注尺度 1、无再加注，6 个发牌、9 个节点、12 个信息集（`src/pokergto/solver/games.py#kuhn`）。它同时是全仓库唯一有完整解析解的含诈唬博弈：博弈值 `−1/18`，均衡是一个**单参数族**。

于是本节要教的不是"怎么跑 CFR"，而是两件更难的事：

1. 手工核对一次迭代，看清频率是怎么被账本推着的；
2. 看清**"解出来的频率"和"理论的频率"不是一回事**。族里的每一个成员都可剥削度为 0，你的运行落在哪一个，取决于代码的轨迹；把它当成结论抄下来，就是本仓库开发中真正的教训。

## 推导 / Derivation

记 P0 用 `J` 开注的频率为 `α`，用 `K` 开注的频率为 `κ`；P1 面对开注时用 `Q` 跟注的频率为 `β`；P1 在 P0 过牌后用 `J` 下注的频率为 `g`；P0 面对下注时用 `Q` 跟注的频率为 `c`。五个量、四条关系，全部来自无差别条件。

**关系 1：`β = 1/3`。** P0 拿 `J`：过牌永远输掉前注（`J` 摊牌必输），价值 `−1`；开注则一半遇到 `Q`（`P1` 跟注率 `β`）：`0.5·[(1−β)(+1) + β(−2)] + 0.5·(−2) = −0.5 − 1.5β`。两者相等 → `β = 1/3`。
含义：**`P1` 的 `Q` 必须恰好三分之一跟注，`α` 才有自由度。** `α` 本身定不住——这正是族存在的原因。

**关系 2：`κ = 3α`。** `P1` 用 `Q` 在 `(0, 1)` 内混合，需要它对跟注与弃牌无差别。开注范围里 `J` 与 `K` 的反事实比是 `α : κ`，所以
`2·α/(α+κ) − 2·κ/(α+κ) = −1` → `κ = 3α`。
因为 `κ ≤ 1`，立刻得到 **`α ≤ 1/3`**：族的边界来自"国王最多每手都下注"这一条物理约束。教科书写作 `α ∈ [0, 1/3]` 的那段区间，其实是 `κ = 3α` 与 `κ ≤ 1` 的推论；而"**头牌总是下注**"恰好是这条线在 `α = 1/3` 的**角点**，不是前提。

**关系 3：`c = 1/3 + α`。** `P1` 在过牌后用 `J`  bluff，两个可达发牌要按**对手 reach** 加权：`P0` 拿 `Q` 时过牌概率 1，拿 `K` 时过牌概率 `1 − κ`。
`J` 下注对过牌的差值：遇 `Q` 为 `(1−3c) + 1 = 2 − 3c`，遇 `K` 为 `−2 + 1 = −1`。加权归零 → `1·(2 − 3c) + (1 − κ)·(−1) = 0` → `c = (1 + κ)/3 = 1/3 + α`。
**注意这里用的是反事实权重，不是"我拿 J 时对手是 Q 或 K 各一半"。** 用后者会得到 `c = 1/3`，与生成物的 `0.5467` 差 0.21——这是一个真实会犯的错（`08-02` 例 5）。

**关系 4：`g = 1/3`。** `P0` 的 `Q` 面对下注要无差别：跟注赢 2 / 输 2、弃牌 −1，需要 `P(J | 下注) = 1/4` → `g/(g+1) = 1/4` → `g = 1/3`（`P1` 的 `Q` 从不过牌后下注，`K` 全下注）。

**验证族。** 用上面四条关系参数化出一个策略，喂给 `exploitability`：

```bash
PYTHONPATH=src python -c "
import numpy as np
from pokergto.solver.games import kuhn
from pokergto.solver.exploitability import exploitability, expected_value
t=kuhn(1.0); idx={l:i for i,l in enumerate(t.infoset_labels)}
def fam(a):
    k=3*a; c=(1+k)/3
    d={'0:0:J':(1-a,a),'0:0:Q':(1.0,0.0),'0:0:K':(1-k,k),
       '1:1:J':(2/3,1/3),'1:1:Q':(1.0,0.0),'1:1:K':(0.0,1.0),
       '2:0:J':(1.0,0.0),'2:0:Q':(1-c,c),'2:0:K':(0.0,1.0),
       '3:1:J':(1.0,0.0),'3:1:Q':(2/3,1/3),'3:1:K':(0.0,1.0)}
    m=np.zeros((t.n_infosets,2))
    for l,i in idx.items(): m[i]=d[l]
    return m
for a in (0.0,0.1,0.213282,1/3): print(a, exploitability(t,fam(a)), expected_value(t,fam(a)))"
# 每个 α 的可剥削度在 1e-17 量级（数值零），博弈值 −0.055555556 = −1/18
```

`α = 1/3` 那一次就是教科书写法（`K` 全下注、`P0` 的 `Q` 跟注 2/3）；`α = 0.213282` 是本仓库那次运行落到的成员。两者都通过可剥削度门限，也都通过 `−1/18` 门限——**这就是为什么断言只能落在关系上，不能落在某一行频率上。**

## 直觉 / Intuition

把均衡族想成一条线，不是一个点：

- `α` 沿线滑动时，P0 的 `J` 始终无差别，P1 的 `Q` 也始终无差别。所以没有任何力量把运行推到某个特定 `α`——CFR 落在哪里，取决于实现细节、截零方式、加权方式，而不取决于理论。
- 线的存在本身就是信息：`P0` 的 bluff 频率不可辨识，意味着**"这个 64% 是不是抄错了"是一个无法用单行回答的问题**，能回答的是关系检查：`3α = 0.639846` 对 `K` 的开注 `0.639918`，差 7.2e-5；`1/3 + α = 0.546615` 对 `Q` 的跟注 `0.5467`，差 8.5e-5。都在 1e-4 量级，与那次运行残余的可剥削度 `1.08e-5` 同一尺寸——不是巧合，是同一个"没收敛干净"的余量。
- 最有价值的一步转换：**从"这手牌该怎么做"到"这一行的频率受什么约束"。** 真实德州的绝大多数争论（该不该总用坚果下注、该不该总用某一档尺度）其实都是均衡选择问题，不是理论问题。

**例 1 — 一次真实的迭代账本（CFR+，Kuhn，前 8 轮）。** 列顺序：节点 0/1 是 `(check, bet)`，节点 2/3 是 `(fold, call)`。

| 轮 | 信息集 | 累计遗憾 `R` | 当前策略 | 平均策略 |
|---|---|---|---|---|
| 1 | `0:0:J` | `[0.0, 0.125]` | `(0, 1)` | `(0.5, 0.5)` |
| 2 | `0:0:J` | `[0.1667, 0.125]` | `(0.571, 0.429)` | `(0.167, 0.833)` |
| 4 | `0:0:J` | `[0.2537, 0.0]` | `(1, 0)` | `(0.6, 0.4)` |
| 8 | `0:0:J` | `[0.2431, 0.1124]` | `(0.684, 0.316)` | `(0.738, 0.262)` |
| 1 | `0:0:K` | `[0.0, 0.125]` | `(0, 1)` | `(0.5, 0.5)` |
| 3 | `0:0:K` | `[0.0, 0.162]` | `(0, 1)` | `(0.237, 0.763)` |
| 8 | `0:0:K` | `[0.0601, 0.1674]` | `(0.264, 0.736)` | `(0.281, 0.719)` |
| 1 | `3:1:Q` | `[0.0833, 0.1667]` | `(0.333, 0.667)` | `(0.5, 0.5)` |
| 8 | `3:1:Q` | `[0.2181, 0.1589]` | `(0.579, 0.421)` | `(0.634, 0.366)` |

三个观察：`0:0:J` 的当前策略在 `(0,1) → (0.571,0.429) → (1,0) → (0.684,0.316)` 之间摆动，而平均策略一路平滑走向 `0.738`；`0:0:K` 的 `check` 那一格在第 3 轮又被截成 0（CFR+ 的性质）；`3:1:Q` 的平均值在第 8 轮已经接近 `1/3`（`0.366`），因为关系 1 定住了它。复算命令在 练习。

还有一处必须说明的实现细节，否则手算会对不上：`cfr.py` 的截零发生在**每一次 `(节点, 发牌)` 更新之后**（`np.maximum(regret_row, 0.0, out=regret_row)` 写在递归里面），不是"一轮累加完再截一次"。所以 `3:1:Q` 第 1 轮的账本是 `[0.0833, 0.1667]` 而不是 `[0, 0.1667]`：发牌 0 更新后先截成 `[0, 0.25]`，发牌 5 的 `+0.0833 / −0.0833` 再加上去，负的那格没有被重新截零。发牌顺序由 `permutations` 固定，所以这仍然是确定性输出（生成物里 `determinism_verified: true`、`seed: 0`），但它意味着：**按"一轮求和再截零"的教科书描述手算，会与这份代码的中间账本不同**。

**例 3 — 把两个成员混一起会发生什么。** 取生成物的 `α = 0.213282`、其余 11 行不动，只把 `0:0:K` 改成"每手都开注"（教科书写法）。这条混合线：

```
可剥削度 = 0.030002 筹码/手（是生成物残余的约 2,800 倍）
博弈值   = −0.055554 筹码/手（照旧通过 −1/18 门限！）
```

**这是本节最重要的一行数据**：把角点的 `κ = 1` 和线中间的 `α = 0.2133` 拼在一起，得到一个不在均衡上的策略，但它的博弈值仍然对——`−1/18` 这条锚抓不住它，只有可剥削度门限抓得住。ADR-0002 要同时上两种机制，原因就在这里。

**例 4 — Kuhn 的开注范围正好落在第 02 章的 1/2 池行。** Kuhn 的下注是 1 进 2 的底池 = 1/2 池。族的任意内点都给出

```
诈唬占开注范围 = α/(α+κ) = α/(4α) = 1/4 = 25.00%
价值 : 诈唬    = 3 : 1
```

用生成物：`0.213282/(0.213282+0.639918) = 0.24998`，`0.639918/0.213282 = 3.0003`。下一节的表会把 `1/2 pot` 那行的代数（0.25 与 3.0）摆在一起——两者是同一件事，一个来自迭代，一个来自代数。

**例 5 — 在 Kuhn 里量 MDF，量错对象会得到假矛盾。** Kuhn 的下注是 1 进 2 的底池，`最低防守频率（MDF） = pot/(pot+bet) = 2/3`。用生成物的 12 行算两种防守比例：

| 量的对象 | 谁 | 数值 | 与 MDF 的关系 |
|---|---|---|---|
| 全体到达范围（含被支配的 `J`） | P0 在节点 2 | 0.422388 | 看着"低于 2/3" |
| 全体到达范围（含被支配的 `J`） | P1 在节点 3 | 0.291672 | 看着"低于 2/3" |
| **真正面对 bluff 的那一段范围** | P0（`Q` 与 `K`，按过牌 reach 加权） | 0.666711 | 就是 2/3（差 4.4e-5） |
| **真正面对 bluff 的那一段范围** | P1（`Q` 与 `K`，等权） | 0.666683 | 就是 2/3（差 1.6e-5） |

原因不是公式失灵，而是**牌力移除**：我拿 `J` bluff 时，对手不可能也拿 `J`，所以那一格根本不在"面对 bluff 的范围"里。把被支配的格子从分母里去掉，MDF 立刻精确成立——两侧面对 bluff 的弃牌比例分别是 0.333289 与 0.333317，而诈唬需要的弃牌率正是 `bet/(pot+bet) = 1/3`。现算：

```bash
PYTHONPATH=src python -c "
import json
rep=json.load(open('data/gen/solver/kuhn.json',encoding='utf-8'))['average_strategy']
a=rep['0:0:J']['bet']; k=rep['0:0:K']['bet']; c=rep['2:0:Q']['call']; b=rep['3:1:Q']['call']
print('P0 bluff-facing defence', (c+(1-k))/(1+(1-k)), 'P1 bluff-facing defence', (b+1)/2)
print('P0 aggregate defence', (c+(1-k))/((1-a)+1+(1-k)), 'P1 aggregate defence', ((a+k)*b+a)/(k+(a+k)+a))"
```

这张表是本节与第 02 章的接缝：`02-03` 说"MDF 是频率总量的地板"，Kuhn 说"要先说清这个总量是按哪个范围加权的"。真实翻后同理——只是没人会在 solver 图上先问这一句。

## 实战牌局 / Live hands

本节的 2 手牌局：第 1 手是一整手 Kuhn 发牌按生成物的频率走到底（求解器手）；第 2 手是把"频率 vs 关系"这条纪律搬到一个真实河牌局面（转移手）。

**牌局 1（`hand.08-03-kuhn-king-versus-queen`）— 发牌 5：P0 拿 `K`，P1 拿 `Q`。**

| 步骤 | 节点 | 信息集 | 频率（`kuhn.json`） | 说明 |
|---|---|---|---|---|
| 1 | 0 | `0:0:K` | bet 0.639918 / check 0.360082 | 36% 的时候头牌选择过牌 |
| 2a | 3 | `3:1:Q` | fold 0.666635 / call 0.333365 | 若 P0 开注，`β = 1/3` |
| 2b | 1 | `1:1:Q` | check 1.0 | 若 P0 过牌，P1 拿 Q 不下注，直接摊牌 |

- 走"开注 → 跟注"（2a）：终局节点 8，支付 `+2`（`terminal_p1_calls = winner·2`）；走"开注 → 弃牌"：终局节点 7，支付 `+1`；走"过牌 → 过牌"（2b）：终局节点 4，支付 `+1`。
- 这一手牌单独看，开注更强：`0.333365·2 + 0.666635·1 = 1.333365` 对 `1.000000`。另一手 P0 拿 `K` 的发牌（发牌 4，P1 拿 `J`）反过来：过牌 `0.666654·1 + 0.333346·2 = 1.333346` 对 开注 `1.000000`。
- **两个发牌平均起来正好相抵**（`0:0:K` 这一行就是这两个发牌）：开注 `1.166683`，过牌 `1.166673`，差 `1.0e-05`——与那次运行残余的可剥削度 `1.08333e-05` 同一量级。现算命令：

```bash
PYTHONPATH=src python -c "
import numpy as np, json
from pokergto.solver.games import kuhn
from pokergto.solver.tree import TerminalNode
t=kuhn(1.0); rep=json.load(open('data/gen/solver/kuhn.json',encoding='utf-8'))['average_strategy']
row=[None]*t.n_infosets
for l,i in {l:i for i,l in enumerate(t.infoset_labels)}.items():
    acts=[n.actions for n in t.nodes if getattr(n,'infosets',None) is not None and i in set(int(x) for x in np.unique(n.infosets))][0]
    row[i]=[rep[l][a] for a in acts]
def u(node,deal,p=0):
    n=t.nodes[node]
    if isinstance(n,TerminalNode): return float(n.payoff[deal]) if p==0 else -float(n.payoff[deal])
    s=row[int(n.infosets[deal])]; return sum(s[a]*u(c,deal,p) for a,c in enumerate(n.children))
print('bet', (u(3,4)+u(3,5))/2, 'check', (u(1,4)+u(1,5))/2)"
# bet 1.1666825 check 1.166673
```

- 这就是"头牌只下注 64%"合法性的直接证明：**无差别发生在信息集层面，不在单个发牌层面。** 一手牌上它明显更好（+0.333），另一手上它明显更差（−0.333），加起来是零——因为对面拿 `Q` 时他只三分之一跟注（`β = 1/3`），对面拿 `J` 时他三分之一会 bluff（`g = 1/3`）。谁若声称" solver 说头牌该 100% 下注"，请他先把这两个发牌的符号相反说清楚。

**牌局 2（`hand.08-03-real-river-value-frequency`）— 单挑，河牌 `Kh9d6s4h2c`，底池 24，你只有坚果同花与空气两类牌，对手有一手抓诈唬牌 `Ad3d`。**

场景（`reference`：作者自建示例，不是任何 solver 的输出）：你河牌下注 12（1/2 池）。

- 教科书式提问："坚果要 100% 下注吗？" Kuhn 给的答案是：**不一定，而且这不是原则问题而是配平问题。** 在 Kuhn 的头牌上，`κ` 被 `3α` 拖下来，是因为对手的 `Q` 只需三分之一跟注就能让我方 bluff 无差别；一旦我方的下注尺度与 bluff 频率变，坚果的下注频率也会跟着变。
- 能直接搬过来的硬结论只有两条：(a) 一旦配平，你的价值与诈唬的比例由尺度定住——`table.02-04` 的 `1/2 pot` 行给出 3 : 1；(b) 面对下注，最强牌跟注是严格占优、最弱牌跟注是严格劣策略（Kuhn 里 `2:0:K` = 1.0、`2:0:J` = 0，生成物满足，门限 1e-3）。
- 不能搬的：本例里对手会多街反应、有多个尺度、牌力抽象会合并信息集（08-06），`κ = 3α` 这类闭式关系不再有解析解。真实 solver 报的"坚果 62% 下注"同样可能是均衡选择，也可能是没跑够；分辨方法在 08-04 的清单里，本节先把问题摆出来。

## 范围图 / Range chart

本节没有可嵌入的范围图：`data/gen/ranges/` 里只有 02-03 那张 MDF 底线图，而 Kuhn 的"范围图"就是一张三行的表——`J` 开注 0.213282、`Q` 开注 0.0、`K` 开注 0.639918（`data/gen/solver/kuhn.json`）。把它画成颜色不会增加任何信息，反而容易诱使人读出根本不存在的"牌力形状"。

值得练的是另一种读法：**先问形状（哪几行是 0 或 1），再问数值。** 本节里形状部分是可断言的：`0:0:Q = 0`、`2:0:J = 0`、`2:0:K = 1`、`3:1:J = 0`、`3:1:K = 1`——全是被占优/严格劣策略锁住的两端；数值部分（`0.2133`、`0.6399`、`0.5467`）不是定理，是族里的一个点。

## 为何成立、何时失效 / Why it works, when it breaks

**为什么 64% 是合法答案。** 三条线同时成立：(1) 它满足 `κ = 3α`（差 7.2e-5，量级等于残余可剥削度）；(2) 在这个策略上 `K` 的开注与过牌反事实价值差 1e-4，即无差别；(3) 整个策略的可剥削度 `1.08e-05` 低于门限 `5e-05`，博弈值 `−0.055556` 与 `−1/18` 相符（`data/gen/solver/kuhn.json` 的 `checks`，五项全 `pass: true`）。

**为什么注册表不断言开注频率。** `proofs.py` 里 Kuhn 的四条断言是：博弈值 `−1/18`、`K` 面对下注跟注 = 1、`J` 面对下注跟注 = 0、`J` 的开注频率 ∈ `[0, 1/3]`（`kind = frequency_bounds`，成员检查而非取值检查）。`assert_jack_bluff_in_family` 的注释写得很直白：要求某一个成员，是在测实现的轨迹而不是测博弈论。这也解释了 `games.py` 文档字符串与生成物的两处不一致：文档里那句 "player 0 bets the king always" 是 `α = 1/3` 角点的写法，本仓库这次跑的是内点（`0.639918`）；同一句文档又把"用 Q 跟注的频率 `alpha + 1/3`"记在 player 1 名下，而生成物里那一格其实是 **P0** 的 `2:0:Q`（0.5467 = 1/3 + α），P1 的 `3:1:Q` 读数是 0.333365。`checks` 里没有任何一条断言涉及 `alpha + 1/3`。`proofs.py#KUHN` 的 `notes` 把第一件事写进了生成物链条，而不是藏起来；第二件事请把它当成本节示范的读法：**文档字符串与生成物冲突时，以生成物与已登记的断言为准。**

**什么时候这套结论失效**：

1. **博弈不是族。** 一旦尺度、街数、玩家数变化，均衡可能变成单点（这时"抄频率"是合法的），也可能仍是族（这时抄了就错）。判断依据不是别人的表，而是能不能写出一个无差别条件把那一行定住。
2. **抽象之后。** 牌力抽象会合并信息集，`α`、`κ` 的含义变粗；08-06 处理它把结论推向哪个方向。
3. **规模不可比。** 6 个发牌、12 行、20,000 轮可以精确解；真实翻后不行，本仓库明确切掉了 6 人桌翻后求解器（`adr/0002` Rule B）。Leduc 是中间那一档，而且现在确实有了：360 个发牌、3,780 行，本文件这种逐牌递归每轮约 0.23 秒，公共树形式每轮约 0.003 秒。它在 `08-04` 里靠什么被验收，请去看那一节——这里没有一个 `-1/18` 可以对拍。
4. **可转移的**：无差别条件决定频率、单行频率不可辨识而关系可辨识、"值对了但策略可剥削"这种失败模式。**不可转移的**：Kuhn 的具体数字，以及"`J` 的 bluff 频率永远自由"这种只在牌堆总共 3 张牌的博弈里才成立的对称性。

## 陷阱 / Common mistakes

1. **把某一行的收敛值当定理。** "solver 说头牌 64% 下注"，然后抄进笔记。
   *代价*：现算的数——把 `κ = 1`（角点）与 `α = 0.213282`（内点）拼在一起，得到可剥削度 **0.030002 筹码/手**的策略，而它的博弈值仍是 `−0.055554`。也就是说：抄错一个成员，你的博弈值检查不会响，可剥削度检查才会响。按每手 0.030 个筹码的漏损计，100 手就是 3.0 个筹码。
2. **只用先验、不用反事实权重算配平。** 用"P0 过牌后，P1 拿 `J` 时对手是 `Q` 或 `K` 各一半"去解 `c`，得 `c = 1/3`；按对手 reach 加权（`Q` 过牌概率 1、`K` 过牌概率 `1 − κ`）得 `c = 1/3 + α = 0.5466`。
   *代价*：现算给你看——把 `c = 1/3` 代进关系 3 的左边，`P1` 用 `J` 在过牌后下注相对过牌的即时差从 `0` 变成 `+0.639918`（未加权；乘上 `1/6` 的发牌权重是 `+0.1067`），恰好等于 `κ`。换句话说：P0 少防守这 0.2133，对手的空气下注每单位频率多赚 0.64 筹码。第 02 章那句"低于最低防守频率（MDF）就是印钱"，在这里是可计算的数字而不是口号。
3. **只检查形状，不看形状的来源。** `0:0:Q = 0` 是占优推论；`3:1:Q = 1/3` 是无差别推论；`0:0:K = 0.64` 两者都不是。
   *代价*：把三类不同置信度的数字当成同一类，然后在最不牢的那一格上下注。本仓库的注册表按这三类的边界来写断言，正是为了让读表的人分得开。
4. **拿可剥削度小当作"每一行都收敛了"。** 族里的点全线可交换：`α` 没收敛到某个值也可以让整条线都可剥削度 0（现算：`α = 0`、`0.1`、`0.213282`、`1/3` 四个成员的可剥削度都在 `1e-17`）。
   *代价*：以为多跑 10 倍轮次会让 `0.2133` 变成某个"真值"。不会——它只是线的当前位置。要判断的是关系残差，不是频率残差。
