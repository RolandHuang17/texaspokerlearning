# 博弈树、信息集与策略组合：一名玩家实际能看见什么

<!-- hands: 2 -->

## 本节目标 / Objectives

- 能用一句话说清节点、信息集、策略组合三者的区别，并指出本仓库的求解器把哪一个当成存储单位。
- 能亲手数出 Kuhn 博弈的 6 个发牌、9 个节点、4 个决策节点、12 个信息集，并解释 12 而不是 24 的原因。
- 能说明"公共树 + 私有向量"为什么是对的心理模型：树是双方共见的，向量是按我自己的底牌切分的。
- 能说出一条策略为什么必须在同一个信息集里保持同一套频率，以及违反它的那类"最优应对"错在哪里。

## 前置知识 / Prerequisites

- `00-02` Derivation over memory：一个数字必须能被引擎重算出来，否则它不算证据。
- `02-04` 无差别条件：混合策略存在的理由是两个动作的期望值相等。

## 核心原理 / The principle

三个对象，不要混：

1. **博弈树**（game tree）： Chance 的所有可能发牌 + 公共决策节点 + 终局节点。本仓库把它存成"每个节点带一个跨发牌的向量"，见 `src/pokergto/solver/tree.py`。
2. **信息集**（information set）：`(节点, 我自己的私有牌)`。同一节点上，只更换对手的底牌，信息集不变。
3. **策略组合**（strategy profile）：从信息集到动作分布的一张表。每个信息集一行，每行是一组和为 1 的频率。

## 推导 / Derivation

Kuhn 博弈：3 张牌 `J < Q < K`，各前注 1，单街，下注尺度 1，无再加注，P0 先行动（`src/pokergto/solver/games.py#kuhn`）。

**发牌。** 两张不同的牌有序发给两人：`permutations(("J","Q","K"), 2)` = 6 个发牌，每个先验概率 1/6：

```
0:(J,Q) 1:(J,K) 2:(Q,J) 3:(Q,K) 4:(K,J) 5:(K,Q)      # 括号内依次是 P0、P1 的牌
```

**节点。** 9 个：4 个决策节点 + 5 个终局节点。

```
node 0  P0: check|bet          node 1  P1(在 P0 过牌后): check|bet
node 2  P0(面对下注): fold|call  node 3  P1(面对下注): fold|call
node 4  check-check 摊牌        node 5  P0 弃牌   node 6  P0 跟注
node 7  P1 弃牌                node 8  P1 跟注
```

**信息集。** 每个决策节点上有 6 个发牌经过，但每个玩家只看得见自己的牌，所以节点 0 的 6 个发牌塌成 3 个信息集（`0:0:J`、`0:0:Q`、`0:0:K`）。代码里能直接看见这一点：

```python
>>> kuhn(1.0).nodes[0].infosets      # 逐发牌的信息集编号
array([9, 9, 10, 10, 11, 11])       # 成对相同 = 按自己的牌合并
>>> kuhn(1.0).nodes[1].infosets
array([6, 7, 8, 7, 8, 6])           # 同一节点，顺序被打乱：合并的是 P1 的牌
```

4 个决策节点 × 3 个私有标签 = **12 个信息集**。计数命令（现场可重算）：

```bash
PYTHONPATH=src python -c "from pokergto.solver.games import kuhn; print(kuhn(1.0).summary())"
# {'deals': 6, 'nodes': 9, 'decision_nodes': 4, 'terminal_nodes': 5, 'infosets': 12}
```

**为什么不是 24。** 24 = 4 节点 × 6 发牌，那是"看得见对手底牌"的决策点数。信息集把对手的那一维抹掉：`tree.py` 的合并键是 `(node_id, player, 我自己的牌)`，从不包含对手的牌，也从不包含公共信息之外的东西。

**同一套代码在单街博弈上的计数。** `one_street_bluff_catcher(pot=1, bet_size=0.5)`：2 个发牌（`nut` 与 `air` 各半）、5 个节点、2 个决策节点、3 个信息集。它的第二个节点上 P1 只有一行——两个发牌都映射到同一个信息集 `1:1:catcher`，因为抓诈唬牌看不出对手拿的是坚果还是空气：

```bash
PYTHONPATH=src python -c "from pokergto.solver.games import one_street_bluff_catcher as g; print(g(1.0,0.5).summary())"
# {'deals': 2, 'nodes': 5, 'decision_nodes': 2, 'terminal_nodes': 3, 'infosets': 3}
```

## 直觉 / Intuition

**公共树 + 私有向量。** 想象一棵树挂在墙上，两人都看得见，包括每一条已经发生的行为。你唯一看不见的是对手那一张牌。于是"你的处境"= 树上的一个节点 ⊕ 你自己手里那张牌。求解器就按这个切分存储：节点是公共的，一个信息集是公共节点上的一个私有切片。

一句话口诀：**策略是一张表，行是信息集，不是节点，也不是手数。**

- 行的数量决定问题的规模：Kuhn 12 行，可以在笔记本上精确解；单街博弈 3 行，可以精确解到 6 位小数。
- 一行的内容是一组频率（`mixed-strategy`），不是一个动作。频率不是"犹豫"，是**让对手无法从你的行为里读出你牌力**的唯一手段（`02-04`）。
- 一张范围图就是这张表在真实博弈里的一层切片：13×13 的每个格子属于某个信息集，格子的颜色就是那一行里那一个动作的频率。

## 算例 / Worked examples

**例 1 — 一个发牌属于哪几行。** 发牌 1 = `(J,K)`：P0 拿 `J`，P1 拿 `K`。这手牌若走"过牌 → 下注 → 弃牌"，它依次落在三行上：`0:0:J`（P0 过牌）→ `1:1:K`（P1 下注）→ `2:0:J`（P0 弃牌）。三个信息集、三行频率，由同一个发牌串起来。注意第 2 行不是 `1:1:J`——那一行属于 P1 拿 `J` 的两个发牌。

**例 2 — 同一信息集里的两个发牌必须同频率。** `0:0:J` 覆盖发牌 0 `(J,Q)` 与发牌 1 `(J,K)`。生成物给这一行的下注频率是 **0.213282**（`data/gen/solver/kuhn.json`，`average_strategy["0:0:J"]["bet"]`）。如果允许"对手拿 Q 时 bluff 30%、拿 K 时 bluff 10%"，那已经不是策略，而是"我知道你的牌"。可剥削度的定义会立刻拒绝它：最优应对必须**每个信息集只选一个动作**（`src/pokergto/solver/exploitability.py`），按发牌取 argmax 算出来的是"偷看牌的人能赢多少"，不是这套策略的性质。

**例 3 — 终局向量的读法。** 节点 5（P0 弃牌）的支付向量是 6 个 −1：与牌力无关，弃牌就是输掉前注。节点 6（P0 跟注）是 `[-2,-2,2,-2,2,2]`：符号完全由 `sign(P0 牌 − P1 牌)` 决定。P1 的支付是 P0 的负数——本仓库所有博弈都是零和，这一点在 `games.py` 的模块注释里写死了"绝对记账"约定：终局支付是**从这手牌开始**的净筹码，前注已经算进去。

**例 4 — 真实德州里这一维有多大。** 翻前一副底牌有 1326 个组合（下表）。如果抽象到手牌类别，是 169 行；抽象到"牌力桶"，可能是 5–9 行。求解器的规模从来不由"节点数"决定，而由**信息集行数 × 每行动作数 × 公共树的街数**决定。这正是 08-06 讲牌力抽象时唯一要权衡的量。

本节的 2 手牌局：第 1 手走求解器——把 Kuhn 的一整手牌逐节点走到底；第 2 手是转移手，用同一套信息集语言重写一个真实河牌局面，其中的数值仍然只取自生成物。

**牌局 1（`hand.08-01-kuhn-jack-versus-king`）— 发牌 1：P0 拿 `J`，P1 拿 `K`。**

| 步骤 | 节点 | 谁在行动 | 信息集（行） | 这一行的频率（来自 `kuhn.json`） | 累计净筹码（P0） |
|---|---|---|---|---|---|
| 1 | 0 | P0 | `0:0:J` | check 0.786718 / bet 0.213282 | 前注已付：−1 |
| 2 | 1 | P1 | `1:1:K` | bet 1.0 | — |
| 3 | 2 | P0 | `2:0:J` | fold 1.0 / call 0.0 | −1 |

- 第 3 步不是"取舍"，是**严格劣策略**的排除：`J` 摊牌必输，跟注只是往输掉的底池里再放 1 个筹码。`proofs.py#assert_jack_never_calls` 断言的正是这一条（实测 0，容差 1e-3）。

**牌局 2（`hand.08-01-river-bluff-catcher-one-row`）— 单挑，河牌 `AsKd7h5c2s`，对手底池下注。**

底池 20，对手下 20。你拿着 `JhTh`，只击败诈唬。

- 你的处境是一个信息集：`(河牌动作节点, JhTh)`。你看不到对手的牌，所以你必须对"对手是坚果"和"对手是空气"这两个真实世界状态**用同一套频率**（`02-03` 的 MDF 配额是 50%，`table.02-03.mdf-vs-sizing` 那一行）。

## 为何成立、何时失效 / Why it works, when it breaks

**成立的前提**：完美回忆（perfect recall）。每个玩家记得自己做过什么、记得所有公共行动，只在私有牌上不可区分。本仓库的 `TreeBuilder` 用 `(node, player, private_key)` 做键，节点本身编码了公共历史，所以完美回忆是结构性保证而不是假设。

它在这几种情形下不再免费：

1. **牌力抽象之后。** 把 `AhKh` 和 `AhQh` 塞进同一个桶，你就造出了一个"看不见自己牌"的信息集。这时策略仍然定义在合并后的行上，但真实最优打法可以在合并前区分它们——误差由此产生，方向由 08-06 讨论。
2. **多人底池。** 每个对手都有自己的私有向量，信息集变成 `(节点, 我的牌)`，但动作分布要对所有对手的联合范围做出反应。零和两人生成的"一行两频率"结构仍在，`s/(1+2s)` 那类配比却变了（`07-01`）。
3. **不完美回忆的博弈。** 真实德州里"我在翻牌过牌、转牌下注"和"我在翻牌下注、转牌过牌"走到同一张公共牌面时，玩家可能记不清自己的线；理论上有专门的困难，本仓库不做。
4. **模型规模。** Leduc 是"免费"到此为止的地方：360 个发牌、85 个公共节点、**3,780 个信息集**，而 Kuhn 只有 12 行。逐牌递归在那里每轮约 0.23 秒，Leduc 登记的 10,000 轮要跑约三十八分钟；`solver/vector.py` 的公共树形式 35 秒跑完同一个解，而它在写出任何生成物之前必须先通过全部已登记的门（`tests/test_solver_vector.py`）。`adr/0002` 拒绝的是"没有验证锚点的博弈"——`tools/run_solver.py` 对不在注册表里的博弈直接报错，因为一棵写错的树会开心地收敛到另一个博弈的均衡——而"有闭式解的两条街玩具"正是这条规则现在还卡住的地方：Leduc 能进来，靠的是三条不需要闭式的门禁，见 `08-04`。
5. **能转移到真实德州的部分**：信息集是一个频率行的原因（你看不见对手）、粒度先于数值的问题顺序、"按发牌取 argmax 不是最优应对"这条纪律。**不能转移的部分**：12 行可以精确解，真实翻后树不行；本仓库明确切掉了 6 人桌翻后求解器（`adr/0002` Rule B）。

## 陷阱 / Common mistakes

1. **把节点当信息集。** "翻牌圈我该怎么打"其实是一个节点；"翻牌圈我拿着这副牌、面对这个下注"才是一行。
   *代价*：在 Kuhn 上，节点数 4、信息集数 12、"看得见对手牌的决策点"数 24。用 24 去估算规模会高估 2 倍，用 4 去写策略则会把不同底牌塞进同一行——那不是策略，是作弊。用 `kuhn(1.0).summary()` 三个数一次看清。
2. **给同一信息集的两个发牌写不同频率。** "他拿 Q 的时候我 bluff，拿 K 的时候我弃"——这是按隐藏信息分支。
   *代价*：你算出来的 EV 会漂亮得可疑，因为求解器的最优应对按信息集 commit，而你的"策略"按发牌 commit，两边不在同一个空间里比。`exploitability.py` 的注释点名了这个错误，`np.bincount(node.infosets, ...)` 那一行就是防它的。
3. **先读数值，再问粒度。** 看到"KTs 在这里 60% 跟注"就记下来，却不问这 60% 是组合层、类别层还是桶层的频率。
   *代价*：桶层的 60% 摊到组合上可能是 40% 与 90% 两组，你在最弱的组合上多花了 20 个百分点。真实代价要用 `python -m pokergto range "22+,ATs+"` 看组合数自己算。
4. **把信息集当成"我知道的信息"的总和。** 公共牌、对手的行为我都知道，它们不区分信息集；它们已经写在节点里了。
   *代价*：重复计数，把同一个决策拆成多行，每行学各自的遗憾——收敛会慢，而且结果与"一行"不等价。
