# 遗憾匹配：只按当初该做什么来迭代

<!-- hands: 2 -->
<!-- terms: regret, regret-matching, cfr, information-set, mixed-strategy, ev-decomposition, indifference, average-strategy -->

## 本节目标 / Objectives

- 能从一组累计遗憾值写出一行的当前频率：正部分、归一化；全非零就取均匀。
- 能手算两次：给一个遗憾向量（两个动作、三个动作各一次），写出下一步策略，并用仓库里那 5 行代码验证。
- 能说清遗憾为什么要按"对手reach × 发牌概率"加权（counterfactual），以及不加权的后果。
- 能指出真正收敛的量不是当前频率，而是频率的历史加权平均（详见 `08-04`）。

## 前置知识 / Prerequisites

- `08-01` 信息集：策略是一张表，行是信息集。
- `02-04` 无差别：混合策略的存在条件是两个动作期望值相等。
- `00-02` 先推导再记忆：本节每个数字都给重算命令。

## 核心原理 / The principle

一个信息集上，累计遗憾记作 `R(I, a)`。当前策略是

```
σ(I, a) = max(R(I, a), 0) / Σ_b max(R(I, b), 0)      当分母 > 0
σ(I, a) = 1 / n                                        当所有 R(I, ·) ≤ 0
```

一行话：**只按"当初该做什么"分配频率；没学到的时候均匀。** 这是 CFR 的全部想法，在本仓库里是 5 行代码（`src/pokergto/solver/tree.py#regret_matching`）：

```python
positive = np.clip(regrets, 0.0, None)
totals = positive.sum(axis=1, keepdims=True)
where = totals > 0.0
uniform = np.full_like(regrets, 1.0 / max(regrets.shape[1], 1))
return np.where(where, positive / np.where(where, totals, 1.0), uniform)
```

## 推导 / Derivation

**遗憾是什么。** 在迭代 `t`，对信息集 `I` 和动作 `a`：

```
ΔR_t(I, a) = π_{-i}^{σt}(I) · chance(I) · ( u(I, a) − u(I) )
```

- `u(I, a)`：从 `I` 出发、先选 `a`、之后双方都按当前策略打的期望筹码（我自己的视角）。
- `u(I)`：按当前策略打的价值 = `Σ_a σ(I, a)·u(I, a)`。
- `π_{-i}(I)`：**对手**走到 `I` 的概率（不含我自己、不含 chance）；`chance(I)` 是发牌概率。

这两项权重是"反事实"三个字的全部含义：**只问我看不见的对手和发牌有多常让我来到这里，不问我自己的频率。** 自己的 `reach` 只进策略和的更新（`cfr.py` 里 `own_weight * reach_self * sigma`），不进遗憾。

**Kuhn 第一次迭代的完整算术。** 起点：`R = 0` → `σ = 均匀 = (check 0.5, bet 0.5)`（所有行都是）。取 P0 拿 `J` 的信息集 `0:0:J`，它覆盖发牌 0 `(J,Q)` 与发牌 1 `(J,K)`。双方下游都按均匀打：

```
u(bet | 发牌 0) = 0.5·(+1) + 0.5·(−2) = −0.5     # P1 拿 Q：一半弃牌(+1)、一半跟注(J 摊牌必输 −2)
u(check | 发牌 0) = 0.5·(−1) + 0.5·(−1.5) = −1.25 # P1 拿 Q：一半过牌摊牌(−1)、一半下注后我再决策(−1.5)
u(bet | 发牌 1) = −0.5，u(check | 发牌 1) = −1.25  # P1 拿 K：数值同形（K 半跟半弃）
u(I) = 0.5·(−0.5) + 0.5·(−1.25) = −0.875
```

于是每个发牌上 `bet` 的即时差 = `−0.5 − (−0.875) = +0.375`，`check` = `−0.375`。权重 `chance = 1/6`、`π_{-i} = 1`（根节点对手还没行动），两个发牌相加：

```
ΔR(bet) = 1/6 · 0.375 · 2 = +0.125
ΔR(check) = −0.125
```

现算验证（`step(0)` 只更新 P0 的行）：

```bash
PYTHONPATH=src python -c "
import numpy as np
from pokergto.solver.games import kuhn
from pokergto.solver.cfr import CFRSolver
t=kuhn(1.0); s=CFRSolver(t); s.iteration=1; s.step(0)
i=list(t.infoset_labels).index('0:0:J'); print(np.round(s.regrets[i],6))"
# [-0.125  0.125]
```

普通 CFR 保留这组 `[-0.125, +0.125]`，遗憾匹配给出 `σ = (check 0, bet 1)`；CFR+ 先把负值截成 0（`cfr.py` 里 `np.maximum(regret_row, 0.0, ...)`），得 `[0, 0.125]`，同一行策略 `(0, 1)`。第 2 次遍历就变成"P0 每次都用 J 下注"。**这就是全章的核心动作：不是"这手牌打得对不对"，而是"下一次该多打哪个动作"。**

**交替更新带来的一个真实细节。** 同一轮里 `step(0)` 先跑，P0 的遗憾已经被改写过；`step(1)` 重新算 `sigma_by_infoset`，于是 P1 看到的是 **P0 更新后的纯策略**（J/Q/K 全部下注 100%）。所以 `3:1:Q` 第一轮截到的增量是 ±0.166667 而不是 ±0.0833：权重从 `1/6 · 0.5` 变成 `1/6 · 1`。测量：

```bash
PYTHONPATH=src python -c "
import numpy as np
from pokergto.solver.games import kuhn
from pokergto.solver.cfr import CFRSolver
t=kuhn(1.0); s=CFRSolver(t); s.iteration=1; s.step(0); s.step(1)
for l in ('0:0:J','3:1:Q'): print(l, np.round(s.regrets[list(t.infoset_labels).index(l)],6))"
# 0:0:J [-0.125  0.125]
# 3:1:Q [-0.166667  0.166667]
```

**收敛的不是这一行。** 当前策略 `σ` 会在几行之间来回摆动；被 `strategy_sum` 累积、按迭代加权的**平均策略**才随可剥削度一起压向 0（`08-04` 用数字说明摆动的幅度）。

## 直觉 / Intuition

把遗憾当成账本，不是情绪。每个信息集有一页，记三件事：

- 我做这个动作时，实际值多少（`u(I, a)`）；
- 按我这套混合打法，这一页平均值多少（`u(I)`）；
- 差值乘上"这件事发生在我看不见的分支上有多频繁"（`π_{-i} · chance`）。

于是：

- **正遗憾 = 我少打了它** → 下一步加频率。
- **负遗憾 = 我多打了它** → 遗憾匹配直接把它当 0 用（不做反向操作）。这一步看着粗糙，却是 CFR+ 更快的来源（`08-05`）。
- **全为 0（开局）→ 均匀**。均匀是"什么都没学到"时唯一不偏向任何动作的答案，也是让账本先跑起来、把信息挣回来的唯一办法。
- **比例是唯一信息**：`[2, −1, 4]` 与 `[1, −0.5, 2]` 给出同一行频率。账本的单位（筹码）可以整体缩放，频率不动——这也是为什么它不需要学习率。

## 算例 / Worked examples

**例 1 — 两个动作，手工两次。** 给定 `R = [3.0, −1.0]`：正部分 `[3.0, 0]`，和 3.0 → `σ = [1.0, 0.0]`。给定 `R = [0.33489, 0.10880]`（这是 Kuhn 里 `0:0:J` 在 CFR+ 跑满 200 轮后的真实账本）：正部分和 = 0.443681，`0.33489/0.443681 = 0.754788`，`0.10880/0.443681 = 0.245212` → `σ = (check 0.754788, bet 0.245212)`。同一轮的平均策略是 `(0.775625, 0.224375)`：两者接近但不相等，差值就是"当前"与"历史"的差。

**例 2 — 三个动作。** `R = [2.0, −1.0, 4.0]` → 正部分 `[2, 0, 4]`，和 6 → `[0.333333, 0, 0.666667]`。把整行缩小一半，`R = [1.0, −0.5, 2.0]`，输出完全相同：`[0.333333, 0, 0.666667]`。缩放无关性由此可验。

**例 3 — 什么都没学到。** `R = [0.0, 0.0]` → `[0.5, 0.5]`；`R = [−0.5, −2.0]` → 正部分 `[0, 0]`，和为 0 → 仍取 `[0.5, 0.5]`。这个分支在代码里靠 `where = totals > 0.0` 实现；漏掉它，第一次迭代会除 0 得到 `nan`，整棵树一起坏掉。

**例 4 — 只有一个动作有正遗憾。** `R = [−4.0, 8.0]` → `[0, 1]`：纯策略。CFR+ 里被截成 0 的那一格不会永远躺平——下一轮它若变好，增量会重新变正。`0:0:Q` 在 200 轮后的账本是 `[0.18547, 0.0]`（check / bet），被截到 0 的正是"用 Q 下注"那一格，所以当前策略是 `(1, 0)`。

**例 5 — 加权的意义。** 如果不用 `π_{-i} · chance` 加权，而是按"这一手我实际打了多少次"来记账，`0:0:J` 的账本会被我自己的频率污染：我越常 bluff，越常进入 `2:0:Q`/`2:0:K` 那些我可能被打回的分支，账本就把"我自己的选择"当成"证据"。这正是本仓库开发中真实踩过的第一类错误的近亲（`08-04` 讲它的症状：停在可剥削度 0.079 的假不动点）。

## 实战牌局 / Live hands

本节的 2 手牌局：第 1 手是 Kuhn 里一个信息集从第 1 轮到第 2 轮的账本变化（求解器手）；第 2 手是把同一套"账本"纪律用到一个真实河牌局面（转移手），其中的算术量取自 `pokergto.ev`。

**牌局 1（`hand.08-02-kuhn-first-ledger`）— `0:0:J`，Kuhn 的第 1 轮。**

- 起点：`R = [0, 0]` → `σ = (check 0.5, bet 0.5)`。
- 遍历结束：`ΔR = [−0.125, +0.125]`（上面 `推导` 里逐项算过；`u(bet) = −0.5`，`u(check) = −1.25`，`u(I) = −0.875`，两个发牌各带权重 1/6）。
- 第 2 轮的当前策略：`(0, 1)`——`J` 每手都下注。
- 第 2 轮会发生什么：对手（此时才在 `step(1)` 里被同等信息更新过一轮）开始用 `Q` 半跟半弃，`J` 的 bluff 增量随之缩水。到 200 轮，账本变成 `[0.33489, 0.10880]`，频率 `(0.754788, 0.245212)`；到 20,000 轮，平均策略停在 `bet 0.213282`（`data/gen/solver/kuhn.json`）。
- 一句话总结：**第 1 轮的账本不是均衡，它只是"对手还不会打"时的事实。** 遗憾匹配的价值在于它会继续改。

**牌局 2（`hand.08-02-river-bluff-ledger`）— 单挑，河牌 `9h6d3c2s7h`，底池 30，对手下 15（1/2 池）。**

你拿着 `AdKd`（同花未成、只赢诈唬）。这一手不看胜率，看账本：你在这个信息集上（`河牌面对 1/2 池下注 + AdKd`）的两种打法。

- 跟注的价值：需要胜率 `15/(30+30) = 25.0%`（`python -m pokergto odds --pot 30` 的 1/2 pot 那行）。
- 诈唬的价值要用**对手的弃牌频率**算，不是用"我这手牌上次赚了还是亏了"算。`pokergto.ev.ev_pure_bluff(30, 15, f)`：
  - 对手弃牌 62% → `0.62·30 − 0.38·15 = +12.9` 筹码/次；
  - 对手弃牌 40% → `+3.0`；
  - 对手弃牌 33.333%（= 1 − MDF，`table.02-03` 里 1/2 池那行）→ **恰好 0**。
- 遗憾匹配的纪律用在这里的意思：**记"这个动作在反事实权重下的差值"，别记"这一手的结果"。** 你上次 bluff 成功拿走 30，不代表 `bet` 有正遗憾——如果对手当时几乎必然跟注，那笔钱是他范围里的空气替你付的，你的账本应该记负。人类复盘最容易犯的正是这个错：按结果记频率，而不是按对手的反应结构记。
- 这条转移的边界要说明白：牌局里的 `f = 62%` 是我假设的对手倾向（`reference`，不是任何 solver 的输出），`12.9 / 3.0 / 0.0` 三个数由 `pokergto.ev` 现算；真实河牌有多个尺度、后续街与移除效应，均衡频率不能从这个玩具算出来。

## 为何成立、何时失效 / Why it works, when it breaks

**为什么成立。** 遗憾匹配保证：跑 `T` 轮后，每个信息集上"最优固定动作本可以多拿的总量"被自己压住了——这正是"regret minimization"的字面意思，而 CFR 把它和树递归缝起来：加权后的即时遗憾只依赖对手与 chance，于是每一行都能独立地"补课"。所有行的总遗憾一起变小，平均策略的可剥削度就变小。这条 `O(√T)` 的保证是教科书结论（本文按 `reference` 处理，见来源表），它的**方向**在本仓库的曲线上可验：Kuhn 的 CFR+ 曲线从 500 轮的 2.45050e-04 走到 20,000 轮的 1.08333e-05（`data/gen/solver/kuhn.json` 的 `curve`），对数斜率约 0.8457，比 `1/√T` 更快、比 `1/T` 略慢。

**什么时候失效**：

1. **信息集编号写错。** 两个不该合并的决策被并成一行（或反之），账本就在错误的世界里最优化。`tree.py` 把编号收在一处、`validate()` 检查"一个信息集的动作数必须一致"，就是防它。
2. **权重写错。** 把对手的概率平方、或把自己的概率乘进遗憾——本仓库真实犯过，症状见 `08-04`。
3. **博弈没有锚点。** 没有解析值可对拍的博弈（如 Leduc、两条街玩具）不实现，也不给生成物：遗憾匹配一定收敛到*某个*东西，那不代表它是对的（`adr/0002`）。
4. **不转移的部分。** 玩具博弈每行只有 2 个动作、街只有 1–2 条。真实翻后的行数是它的几个数量级，机制相同、规模不可比。

## 陷阱 / Common mistakes

1. **把当前策略当答案。** 账本说"下一步多打哪个"，没说"这就是均衡"。
   *代价*：200 轮时 Kuhn 的当前策略可剥削度是 2.557e-02 筹码/手，同一时刻平均策略是 2.919e-04（同一份代码、同一次运行；命令见 练习）。抄当前策略，等于把 88 倍的误差抄进计划。
2. **忘了全非正时要走均匀。** `totals > 0` 那个分支不是装饰。
   *代价*：第一轮所有 `R` 都是 0，`0/0` 传播成 `nan`，整棵树一起废掉，而 `nan` 很容易在几十轮之后才第一次被看见。用 `poker` CLI 看不到这件事，用 `regret_matching(np.array([[0.0, 0.0]]))` 一秒看到。
3. **按自己的频率加权遗憾。** 把 `reach_self` 乘进遗憾更新（而不是只乘进 `strategy_sum`）。
   *代价*：收敛到一个假的不动点。`cfr.py` 的注释写着这一行的两种用途，写反是本仓库开发史上第一号 bug 的近亲。
4. **误以为频率依赖账本的绝对大小。** `R = [2, −1, 4]` 与 `R = [1, −0.5, 2]` 给出同一个 σ。
   *代价*：不是 bug，但会带来错误的直觉："把遗憾放大 10 倍就等于更激进"。它等于什么都没有变；真要让某一行更激进，只能改变它的相对结构。
5. **跨信息集累加遗憾。** 把节点 0 和节点 2 的账写进同一页，等于允许"我翻牌的行为影响我转牌的频率"这种作弊式耦合。
   *代价*：频率不再是那一手决策的函数，`08-01` 的定义被破坏；这类错误通常只在可剥削度里暴露，肉眼看不出来。

## 练习 / Drills

- 手算后验证：`R = [5.0, −2.0]`、`R = [1.0, 3.0, −3.0]`、`R = [−1.0, −1.0, 0.0]`。
  `PYTHONPATH=src python -c "import numpy as np; from pokergto.solver.tree import regret_matching as rm; [print(v,'->',rm(np.array([v]))[0]) for v in ([5.0,-2.0],[1.0,3.0,-3.0],[-1.0,-1.0,0.0])]"`
