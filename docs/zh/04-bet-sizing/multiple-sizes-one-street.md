# 一条街用两个尺度：混合尺度如何切分范围

<!-- hands: 2 -->
<!-- terms: size-set, mixed-strategy, betting-frequency, checking-frequency, bet-size, indifference, combos, value-range, bluff-range, spr -->

## 本节目标 / Objectives

- 能对一个给定的尺度对（例如 1/3 池与 3/4 池），用引擎算出两者期望值相等的那一个"临界胜率"，并说明每个尺度各自承载哪一段牌力。
- 能用 `pokergto.theory.frequencies.value_bluff_split` 把"可用的价值组合数与诈唬组合数"按尺度分配，并验证每个尺度的诈唬占比都恰好落在无差别点上。
- 能说出本节哪些结论是结构性的（配额与临界胜率），哪些是本仓库无法求解的（同一条街多尺度的混合频率），并把后者标为 UNVERIFIED。

## 前置知识 / Prerequisites

- `04-01` 尺度由频率与范围两条路径共同治理；本节只处理"下注方一侧"的分配。
- `02-04` 每个尺度的诈唬占比 `B/(P+2B)` 与配比 `(P+B)/B`；`02-03` MDF 给出对手必须留下的组合数。
- `03-07` SPR 决定一个尺度是否还只是尺度（见下文 `table.04-03.size-ceiling-by-stack`）。

## 核心原理 / The principle

一条街上有两个尺度时，可核验的结构只有两件事，两者都能用 `pokergto.ev` 与 `pokergto.theory.frequencies` 算出来：

1. **配额**：每个尺度各自的下注范围必须满足 `诈唬占比 = B/(P+2B)`。两个尺度就是两个独立的配额，不是共享一个配额。
2. **临界胜率**：给定两个尺度各自的弃牌率 `f₁, f₂`，存在一个胜率 `ē`，使 `EV(bet₁) = EV(bet₂)`；`ē` 以上归大尺度，`ē` 以下归小尺度。`ē` 由 `ev_bet` 两支相等直接解出，是 `derived`。

**而"哪一手牌以多大频率混用两个尺度"不是本节能算的**：本仓库求解决的玩具博弈每个都只有一个下注尺度（`data/gen/solver/toy_1street_*.json`），没有任何生成物产生跨尺度的混合。那一部分标 UNVERIFIED。

## 推导 / Derivation

记：底池 `P`，两个尺度 `B₁ < B₂`，对手面对它们的弃牌率分别是 `f₁, f₂`，被跟注时的胜率 `e`。两条下注支的期望值都来自 `pokergto.ev.ev_bet`：

```
EV(betᵢ) = fᵢ·P + (1 − fᵢ)·( e·(P + 2Bᵢ) − Bᵢ )
```

令两者相等，`e` 是一次项，其余是常数，解出一个闭式：

```
ē = [ (f₂ − f₁)·P + (1 − f₁)·B₁ − (1 − f₂)·B₂ ] / [ (1 − f₁)(P + 2B₁) − (1 − f₂)(P + 2B₂) ]
```

**这一步可能失败的地方是分母。** 分母是两个尺度"被跟注时的最终池子"之差，它会变号：当 `f₂` 大到让大尺度也拿到足够弃牌率时，分母翻正、`ē` 落到 0 或负数，此时"两个尺度各有其段牌力"这句话根本不成立——大尺度对所有 `e ≥ 0` 都更好。这不是数值意外，而是本节最重要的警告（见例 3）。

闭式里还藏着一个不用算的极限：若 `f₁ = f₂`（两个尺度面对同一个弃牌率），分子分母里的 `f` 项全部消掉，

```
ē = (1 − f)(B₂ − B₁) / [ 2(1 − f)(B₂ − B₁) ] = 1/2
```

也就是说，**弃牌率不随尺度变化时，分界线恒等于 1/2**：领先的牌归大尺度，落后的牌归小尺度，与两个尺度的具体数值无关。`ē` 只有在"大尺度买到更多弃牌"（`f₂ > f₁`）时才往下掉，掉到 0 就没有分界线了。

第二个结果是配额分配。若某条线上一共有 `V` 个价值组合数与 `A` 个诈唬组合数可用，把它们分给两个尺度记为 `V₁, V₂` 与 `A₁, A₂`，则"两个尺度都不可被剥削"要求两条等式同时成立：

```
Aᵢ / (Vᵢ + Aᵢ) = Bᵢ / (P + 2Bᵢ),   i = 1, 2
```

未知数四个、等式两条，所以要指定一个尺度承载多少总组合数才能定解。`pokergto.theory.frequencies.value_bluff_split(P, B, 总组合数)` 就是这个方程的解，`bluff_indifference_gap` 用来回验残差为 0。

## 直觉 / Intuition

把一条街想成两块独立的"摊位"：小尺度的摊位便宜，所以每卖出 1 手诈唬需要配 4 手价值（1/3 池，4 : 1）；大尺度的摊位贵，每 1 手诈唬只需配 1.33 手价值（3/4 池，2.33 : 1）。两个摊位各自遵守自己的配比，合起来才不给人留攻击缝。

至于分界线：手牌"值多少"取决于他弃不弃，而他弃多少取决于尺度。两个尺度给出两个弃牌率，于是牌力轴被切成两段——**不是"强牌打大、弱牌打小"这么一句口号，而是一条能解出来的数 `ē`**，例 1 里它等于 45.00%。

## 算例 / Worked examples

**例 1 — 两个尺度的临界胜率（`P = 20, B₁ = 20/3` 即 1/3 池、`f₁ = 25%`；`B₂ = 15` 即 3/4 池、`f₂ = 30%`）。**

闭式给出 `ē = −0.225 / −0.5 = 0.45`。三条期望值核对：

| 被跟注胜率 `e` | EV(1/3 池) | EV(3/4 池) | 归属 |
|---|---|---|---|
| 0.40 | 10.000000 | 9.500000 | 小尺度 |
| 0.50 | 12.500000 | 13.000000 | 大尺度 |
| 0.90 | 22.500000 | 27.000000 | 大尺度 |

复现：`PYTHONPATH=src python -c "from fractions import Fraction as F; from pokergto import ev; print(ev.ev_bet(20,20/3,F(1,4),F(2,5)), ev.ev_bet(20,15,F(3,10),F(2,5)))"`。`ē = 0.45` 就是这条街的"分界线"，它是算出来的，不是画上去的。

**例 2 — 配额分配（可用牌力：60 个价值组合数 + 20 个诈唬组合数）。** 若两个尺度各自承载 40 个组合数：

- 1/3 池：`value_bluff_split(1, 1/3, 40)` → 32 价值 + 8 诈唬（占比 20.00%，配比 4 : 1）。
- 3/4 池：`value_bluff_split(1, 3/4, 40)` → 28 价值 + 12 诈唬（占比 30.00%，配比 2.33 : 1）。
- 合计正好 60 价值、20 诈唬，两个残差 `bluff_indifference_gap` 都是 `0.0`。
- 换句话说：**同一副牌力，换成大尺度去下注，就要多带 4 个诈唬组合数、少带 4 个价值组合数**。这是尺度的机会成本，可算，且与"感觉上大尺度更凶"无关。

**例 3 — 分母翻号的退化情形。** 取 `f₁ = 25%`（1/3 池的 MDF 补）与 `f₂ = 50%`（底池的 MDF 补），`B₁ = 1/3, B₂ = 1, P = 1`：`ē = 0`。此时任意 `e > 0` 都偏好大尺度，两个尺度的分界线不存在。同一条规律推广到整条阶梯：当每个尺度都恰好拿到"理论要求的弃牌率"时，`EV` 对任何 `e ≥ 0.3` 都随尺度单调上升，而 `e = 0` 的空气在 8 个尺度上的期望值全部精确为 `0`。所以**这条街该用几个尺度，不能由这条街自己的算术决定**（复现命令见来源表）。

## 实战牌局 / Live hands

**牌局 1（`hand.04-04-two-size-allocation`）— 翻牌圈 `9h6d3c`，底池 30 bb，我方在 CO，范围里可下注的牌力估为 60 个价值组合数 + 20 个诈唬组合数；尺度集合 {1/3 池, 3/4 池}。**

- 配额：1/3 池承载 40 个组合数 → 32 价值 + 8 诈唬；3/4 池承载 40 个组合数 → 28 价值 + 12 诈唬（`value_bluff_split`，例 2 同一命令把 `P = 1` 换成 `P = 30` 时数值按比例不变，因为占比只依赖 `B/P`）。
- 分界线：`ē = 45.00%`。3/4 池那一摊拿走 `e ≥ 45.00%` 的价值段顶部与全部 12 个诈唬；1/3 池那一摊拿走 `e < 45.00%` 的薄价值段与剩下的 8 个诈唬。
- 决策：`e = 0.40` 的那 4 个组合数打 1/3 池，打 3/4 池每手少 0.5 个筹码（`EV` 10.000000 对 9.500000，`P = 20` 口径）。
- 代价：如果反过来把 20 个诈唬全塞进 1/3 池，让它和价值段顶部的 32 个组合数一起下注（52 个组合数），该尺度的诈唬占比变成 `20/52 = 38.46%`，而无差别点要求 20.00%，`bluff_indifference_gap = +0.184615` → 对手用任意抓诈唬牌跟注都赚，我的薄价值段失去全部跟注。

**牌局 2（`hand.04-04-stack-ceiling`）— 转牌圈 `9h6d3c2s`，底池 12 bb，有效筹码 8 bb，想用 {1/3 池, 2 倍池} 两级。**

- 2 倍池在这个深度是 24 bb > 8 bb，不合法；`table.04-03.size-ceiling-by-stack` 的 `pot_bb = 6, stack_bb = 8` 那行给出同一结论：最大下注 1.3333 倍底池，`largest_standard_size_bb = 6`，且"底池下注即套池"（`pot_size_bet_commits = true`）。
- 于是尺度集合只剩 {1/3 池, 全下}，配额也随之改变：1/3 池 `f = 25%`、全下 `f = 0`（对手要么跟要么弃，且跟注后无后续街）。
- 决策：两个尺度都用同一个弃牌率 `f = 25%` 估（全下与 1/3 池在这个深度买到的弃牌率差不多），闭式立刻退化成 `ē = 1/2`。于是 `e = 0.45` 的手牌归小尺度：`EV(1/3 池) = 6.75` 对 `EV(全下) = 6.45`，差 `0.30` 个筹码；`e = 0.90` 反过来，`13.50` 对 `15.90`，归大尺度。复现：`PYTHONPATH=src python -c "from pokergto import ev; print(ev.ev_bet(12,4,0.25,0.45), ev.ev_bet(12,8,0.25,0.45), ev.ev_bet(12,4,0.25,0.9), ev.ev_bet(12,8,0.25,0.9))"`。
- 这一牌局的作用是把"两个尺度"从审美变成约束满足问题：SPR 先删掉非法选项，配额与 `ē` 再分配剩下的。

## 为何成立、何时失效 / Why it works, when it breaks

**成立的前提**：一条街、`f₁, f₂` 是给定的输入（不是测出来的）、`e` 与被跟注范围一致（同一手牌的被跟注胜率不因尺度而变——这是本节最大的简化）、两个尺度的配额独立结算。

**失效之处**：

1. **`e` 随尺度变。** 真实牌局里大尺度会逼出更强的跟注范围，于是 `e₁ > e₂`，`ē` 闭式失效。本仓库没有"给定尺度求跟注范围"的能力：`02-07` 的薄价值推导把 `q` 当输入，这里也一样。把 `e` 当常数得到的分界线是 **`reference` 级简化**。
2. **混合频率不在这里求解。** 一条街上两个尺度的实际混合比例（哪手牌 70% 打小、30% 打大）需要一个"演员真的在两个尺度之间选"的解。`PUBLISHED_PROOFS` 里的 5 个一街玩具每个只有一个尺度；Leduc 已经实现、也是本仓库唯一有两条下注街的博弈，但它每街同样只有一个尺度（`bet_flop`、`bet_turn`），所以没有任何已登记的博弈给出这个选择。**UNVERIFIED**；路径是一个"同街两尺度"且锚点不依赖闭式解的博弈。
3. **过牌的那一半没有被本节证明。** 目标里"两个尺度如何共用过牌线"的可算部分是组合数守恒：`1326 − 下注组合数 = 过牌组合数`，配额一旦确定，过牌线剩下的牌力段就随之确定。至于"过牌线里必须留什么"是 `04-07` 的主题，本节只引用它的计数。
4. **跨街。** 若尺度集合跨两条街（翻牌小注 + 转牌大注），`EV` 要按后续街重算，本节全部闭式只覆盖单街。
5. **多人底池。** `f` 是"所有人一起弃"，与单个防守者的频率不同（`pokergto.odds.defense_frequency_multiway`）。

## 陷阱 / Common mistakes

1. **把"两个尺度的配比"当成"整条街一个配比"。** 配额按尺度结算：1/3 池要 20.00% 诈唬、3/4 池要 30.00%，把 80 个组合数当成一个池子按 25% 分配会得到错误形状。
   *代价*：牌局 1 里 `bluff_indifference_gap = +0.184615`，即 1/3 池那一摊多带 18.46 个百分点的诈唬，对手的抓诈唬牌由无差别变成稳定盈利。
2. **以为"强牌打大、弱牌打小"是普适规律。** `ē` 存在的前提是分母不为 0 且 `ē > 0`；例 3 显示当弃牌率恰好落在 MDF 补上时 `ē = 0`，分界线消失。
   *代价*：把这条直觉当定理，会在对手守线时系统性欠下注大尺度。
3. **忽略 SPR 对尺度集合的裁剪。** 8 bb 深度谈 2 倍池是非法动作。
   *代价*：`table.04-03.size-ceiling-by-stack` 第一行，`max_bet_as_pot_fraction = 1.3333`；按 2 倍池设计的两级策略在该行完全无法执行。
4. **把混合频率写成确定策略并声称是本仓库算的。** 那些数字只能来自别的求解器，本仓库的许可与证明链都不认。
